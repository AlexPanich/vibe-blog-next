# 46. Срок блокировки пользователя

| | |
|---|---|
| Статус | черновик — решения предложены, не обсуждены |
| Lifecycle | `user.md` — бан и разбан |
| Источник идеи | спека 42, «Не сделано»: выбор «7 дней / 30 дней / Навсегда» в карточке «Блокировка» |
| Зависит от | 02 (бан), 26 (блокировка), 42 (вид карточки пользователя) |

## 1. Цель

Сейчас бан бессрочный: `users.bannedAt` + `banReason`, снимает только admin. В макете
«Админ — Пользователь» у блокировки есть срок.

## 2. Решения (предложены)

1. Варианты срока: 7 дней, 30 дней, навсегда (по умолчанию — 30 дней? см. вопросы).
2. Новое поле `users.banned_until` (NULL = навсегда). В журнал срок пишется отдельной
   колонкой `user_admin_actions.until`, а не в `comment` (там причина).
3. Проверка при входе (`databaseHooks.session.create.before`): бан действует, если
   `bannedAt` есть и (`bannedUntil` NULL или в будущем). Истёкший — снимается лениво при
   попытке входа (обнуляем поля, пишем в журнал `unbanned` с actor = система) и задачей
   очереди раз в час — чтобы списки «Заблокированные» были честными.
4. Пользователь видит в форме входа причину и дату окончания.
5. Уведомление о разбане по сроку — то же, что при ручном (`Ваш аккаунт разблокирован`).

## 3. Данные

`users.banned_until`, `user_admin_actions.until` — `ADD COLUMN`. Actor «система» —
открытый вопрос (NULL в `actor_id` сейчас запрещён).

## 4. UI

Карточка «Блокировка» в «Админ — Пользователь»: причина, три варианта срока пилюлями,
кнопка «Заблокировать». В списке пользователей у заблокированного — «до 12 дек» или
«навсегда».

## 5. Вне scope

Частичные ограничения (только комментарии, только посты), бан по IP.
