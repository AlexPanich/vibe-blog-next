## 1. Цель

Макет кабинета (спека 42) показывает уведомления, которых у нас нет или которые беднее макета:

- «Анна Ли **поставила 5** посту «…»» — уведомлений об оценке нет вовсе;
- «**Новый подписчик**» — подписка на автора уведомлений не создаёт;
- «Дмитрий Рябов: **«А где ночевали…»**» — в уведомлении о комментарии нет его текста;
- «Марат Хасанов **написал вам 3 сообщения**» — у нас заголовок и текст совпадают
  («Новые личные сообщения» / «Новые личные сообщения»), нет ни числа, ни рода.

И найденный при проверке 49 баг: два сообщения подряд дают два уведомления «Новые личные
сообщения», хотя текст во множественном числе.

Новые типы — это новые поводы для спама: переоценка 1→5→1 и отписка-подписка по кругу не
должны засыпать автора колокольчиком.

## 2. Как сейчас

- `notify(tx, type, recipients, target)` пишет строку в транзакции действия, «не себе»,
  социальные типы (`SOCIAL_TYPES`) режет блокировка, хвост — 200 на получателя.
- Текст и ссылка не хранятся — считаются при показе (`notificationText.ts`), вид по типу —
  `notificationLook.ts` (иконка, тон, заголовок, подпись действия).
- `message.created` — «одно **непрочитанное** на диалог»: новое сообщение заменяет висящее
  непрочитанное (`messageNotifications.ts`). Но открытие диалога читает уведомление, и
  следующее сообщение создаёт новую строку — отсюда два «Новых личных сообщения» подряд в
  истории.
- Оценка — `post_ratings` (`postId`, `userId`, `value`, upsert), снять — `value = 0` (строка
  удаляется). Подписка — `user_follows`, отписка удаляет строку.
- Рода у пользователя нет: есть только `nameGenitive` (спека 41).

## 3. Решения (обсуждены 2026-11-10)

Открытые вопросы 1–5 черновика решены человеком: род — необязательное поле; оценка — и смена,
не чаще раза в сутки; группировку комментариев и оценок делаем; уведомлять обо всех оценках;
выдержка и у `comment.edited`. Остальное ниже — следствия этих решений, принятые по аналогии.

### Новые типы

1. **`post.rated`** — автору поста: пост оценили или оценку изменили. Обо всех оценках,
   1–5 тоже. Актор — оценивший. Социальный тип: блокировка режет. Снятие оценки (`value = 0`)
   уведомлений не создаёт.
2. **`user.followed`** — пользователю, на которого подписались. Ссылка — на профиль
   подписчика (`/authors/<id>`). Социальный тип. Подписка на рубрику уведомлений не создаёт:
   у рубрики нет владельца.
3. Отписка и снятие оценки висящее уведомление **не удаляют**: это факт, который был.

### Антиспам

4. **Пара актор–цель — не чаще раза в сутки для оценки и один раз для подписки.** Память —
   отдельная таблица `notification_throttles` (`actorId`, `kind`, `targetId`, `notifiedAt`,
   PK по трём первым): `kind = 'rate'` — `targetId` = пост, `'follow'` — `targetId` =
   пользователь. Перед `notify`: оценка — пропустить, если `notifiedAt` моложе 24 часов;
   подписка — пропустить, если строка есть вообще. После уведомления — upsert `notifiedAt`.
   Флаг в `post_ratings` / `user_follows` не годится: снятие оценки и отписка удаляют строку,
   и флаг пропал бы вместе с ней — снять и поставить заново было бы обходом.
5. Значение оценки **не хранится в уведомлении** — показывается текущее из `post_ratings`.
   Смена в пределах суток новой строки не даёт, но висящая строка уже показывает новое
   число. Оценка снята — строка без числа («оценила пост»).

### Группировка

6. **Группа — одна непрочитанная строка** на ключ:

   | тип | ключ группы |
   |---|---|
   | `comment.created` | получатель + пост |
   | `comment.reply` | получатель + пост |
   | `post.rated` | получатель + пост |
   | `user.followed` | получатель (по аналогии с оценками) |
   | `message.created` | получатель + диалог |

   Новое событие при висящей **непрочитанной** строке группы удаляет её и вставляет новую с
   `groupCount + 1`, свежим `actorId`, `commentId` и `createdAt` — так строка поднимается
   наверх (как сейчас сообщения) и приходит обычным `notification.created` по SSE. Прочитали
   строку — следующее событие начинает новую группу. Остальные типы не группируются.
7. **Сообщения — исключение: одна строка на диалог всегда**, прочитанная тоже заменяется.
   Это чинит баг из 49. Число сообщений — не `groupCount`, а непрочитанные входящие в
   диалоге (`messages.readAt IS NULL`) при показе: «3 новых сообщения»; прочитано — без
   числа.
8. **Уборка группы.** Удаление комментария удаляет уведомления с его `commentId` только при
   `groupCount = 1`; иначе — `groupCount − 1` и `commentId = null` (строка без выдержки).
   Скрытые модератором комментарии остаются в счёте, выдержки у них нет.
9. **Хвост 200** считает строки, а не события — группа одна строка.

### Выдержка

10. **Считается при показе** по `commentId`: `comment.created`, `comment.reply`,
    `comment.edited` (новый текст после правки модератором). Первые ~80 символов, markdown
    срезан до текста, обрезка по слову с «…». Скрытый, удалённый или `commentId = null` — без
    выдержки. Колонку текста в `notifications` не заводим.

### Род

11. **`users.gender`** — `'m' | 'f' | null`, необязательное. В профиле (`office/profile`, рядом
    с родительным падежом) — «Как писать о вас в уведомлениях: оценил / оценила / не
    указывать». Нигде больше не показывается и в публичный профиль не попадает. Миграция —
    `ADD COLUMN` с CHECK на колонке (`users` — таблица со ссылками).
12. **Род влияет только на глагол актора** в одиночной строке (`groupCount = 1`). Группа —
    множественное число, род не нужен. Не указан — безродовая форма. Модерация («Модератор
    скрыл…») не меняется — там актор не называется.

### Тексты

Имя актора — в начале строки, как сейчас (спека 42). `N` — `groupCount − 1`.

| тип | одиночная, м / ж | одиночная, без рода | группа |
|---|---|---|---|
| `post.rated` | оценил / оценила пост «X» на 5 | оценка 5 посту «X» | и ещё N оценили пост «X» |
| `user.followed` | подписался / подписалась на вас | новый подписчик | и ещё N подписались на вас |
| `message.created` | написал / написала вам 3 сообщения | 3 новых сообщения | — (одна строка на диалог) |
| `comment.created` | «выдержка» | «выдержка» | и ещё N: новые комментарии к посту «X» |
| `comment.reply` | «выдержка» | «выдержка» | и ещё N: ответы на ваш комментарий к посту «X» |

Числа — с правильным склонением («1 сообщение», «3 сообщения», «5 сообщений»; «ещё 1», «ещё 4»).
У комментариев пост называется в заголовке строки («Комментарий к посту «X»»), поэтому
выдержка в тексте — без поста.

### Вид

13. `notificationLook`: `post.rated` — `IconStar`, тон `sun`, заголовок «Оценка поста»,
    действие «Открыть пост»; `user.followed` — `IconUserPlus`, тон `mint`, «Новый подписчик»,
    действие «Профиль». У `message.created` заголовок — «Личные сообщения»: текст с числом с
    ним больше не совпадает.
14. **Тосты** (спека 29) — для новых типов как для остальных социальных; для группы тост
    показывает свежее событие.

## 4. Данные

- `NOTIFICATION_TYPES` += `post.rated`, `user.followed` (enum только в TS, CHECK по типу нет —
  проверить на `generate`).
- `notifications.group_count` — `integer NOT NULL DEFAULT 1`, `ADD COLUMN`.
- `users.gender` — `text`, CHECK `gender IS NULL OR gender IN ('m', 'f')`, `ADD COLUMN`.
- Новая таблица `notification_throttles` (`actor_id`, `kind`, `target_id`, `notified_at`),
  PK (`actor_id`, `kind`, `target_id`). Уборки не нужно: строк не больше, чем оценок и подписок.
- Поиск группы — по `(userId, type, postId, readAt)` / `(userId, type, readAt)`: хватит ли
  `notifications_user_read_idx` — решить в плане.
- Сид: `gender` у части демо-людей (и у части — нет), одиночные и групповые `post.rated`,
  `user.followed`, группа комментариев с выдержкой, диалог с 3 непрочитанными.
- Lifecycle: `post.md` — оценка уведомляет автора; `user.md` — подписка и поле рода;
  `message.md` — одна строка на диалог; `comment.md` — группа и уборка.

## 5. Вне scope

Настройки «не присылать» по типам, письма, уведомления об избранном и о взятии на ревью,
вкладки по типам на странице уведомлений (спека 44), сортировка по `createdAt`, группировка
типов модерации.

## 6. Отклонения при реализации

- **Тот же актор счёт не увеличивает** (план, реш. 2). Новое событие при висящей строке группы
  с тем же актором заменяет и поднимает строку, но `groupCount` не растёт: иначе повторная
  оценка через сутки или два комментария одного человека подряд давали бы «Аня и ещё 1». Актор
  хранится только последний, глубже не смотрим.
- **Ссылка группы подписчиков** (план, реш. 10) — `/office/follows?tab=followers`, а не профиль
  последнего: несколько человек — список. Одиночная — `/authors/<id>`, как в реш. 2.
- **Уборка удалённого комментария** (план, реш. 11). Строка группы помнит только последний
  `commentId`: удаление последнего — `groupCount − 1` и строка без выдержки, а комментарий из
  середины группы счёт не уменьшает. Пересчитывать группу не стали. `actorId` группы остаётся
  актором удалённого комментария.

## 7. Проверка (2026-11-10)

`npx tsc --noEmit` — чисто, `npm run lint` — 0 ошибок (старые предупреждения `<img>`). В браузере —
субагент (`app-run`) на демо из сида, по шагу 11 плана. Ошибок в консоли и ответов ≥ 400 нет.

**Работает:** сид у Бориса — группа подписчиков «… и ещё 4», группа оценок «… и ещё 3», «Константин …
написал вам 3 сообщения», группы и выдержки комментариев, одна строка на диалог. Оценка: смена
1→5 — одна строка с числом 5, снятие — строка остаётся без числа, повтор в пределах суток новой не
даёт; второй оценивший — «Марат Хасанов и ещё 1 оценили пост», старая строка у открытой страницы
заменилась без перезагрузки, тост — свежее событие. Подписка → отписка → подписка — одно
уведомление. Род в профиле: «Не указывать» → «Имя: новый подписчик», возврат — снова глагол, выбор
сохраняется. Сообщения с прочтением между ними — всегда одна строка, «написал вам 1 сообщение».
Выдержка без markdown, обрезка по слову; группа комментариев 2 → удаление последнего — счёт 1,
без выдержки. Колокольчик в тёмной теме, длинные названия переносятся, у inline-текстов нет «: ».

**Найдено, не исправлено:**

- Сид пишет `post.rated` до комментариев, а список сортируется по id: непрочитанная группа оценок
  Бориса — после старых комментариев, на второй странице. В рабочем режиме новая строка всегда
  получает больший id, так что это только демо.
- Подписчики dan и katya из сида уже имеют бессрочный throttle `follow` на Аню — уведомления от них
  не будет. Так и задумано (реш. 4), для ручной проверки брать того, кто не подписан.
- Удаление последнего комментария группы оставляет актором автора удалённого («Катя Лис: Новый
  комментарий…», хотя остался комментарий Данила) — следствие реш. 11 плана, читается странно.
- Старые типы и комментарий без выдержки — «Имя: Новый …» с заглавной после двоеточия, как до 51.
