# 05. Лента: поиск, сортировка, фильтры, бесконечная прокрутка

| | |
|---|---|
| Статус | done |
| Lifecycle | не меняется: лента показывает только `published` |
| Источник идеи | next-2, спеки 20 «Сортировки и период», 37 «Серверный поиск», 32 «Бесконечная прокрутка» |

## 1. Цель

Лента `/posts` сейчас — все опубликованные посты одним списком, свежие сверху, и фильтр
по рубрикам (спека 04). Спека добавляет поиск, сортировки, фильтры по автору и периоду и
бесконечную прокрутку порциями. Всё считает сервер, всё состояние — в URL.

## 2. Решения

### Поиск

1. **Серверный, по заголовку и тексту.** Клиентского поиска нет.
2. **Регистр снимает функция SQLite, написанная на JS**: в `globals/db.ts`
   `sqlite.function('lower_ru', …)`. Запрос — `lower_ru(title || ' ' || content) LIKE ?`.
   `lower()` в SQLite кириллицу не понижает. В отличие от next-2 — без колонки
   `searchText`: не нужно заполнять старые посты и помнить о ней при каждой правке
   текста. Полный просмотр таблицы — но `LIKE '%…%'` индекс не использует и с колонкой.
3. **`%`, `_` и `\` в запросе экранируются**, `ESCAPE '\'`: иначе «100%» искало бы
   «100» и что угодно после.
4. **По Enter или кнопке**, обычной GET-формой: работает без JS, каждый поиск — запись в
   истории, нет запроса на каждую букву. Остальные условия форма передаёт скрытыми
   полями.
5. **Минимальной длины нет**, пробелы по краям обрезаются, пустой запрос — поиск
   выключен.
6. **Поиск соединяется со всеми условиями по «И»**: рубрики, автор, период.

### Сортировка и фильтры

7. **Сортировки: новые (по умолчанию), старые, по автору.** «По автору» — группировка:
   авторы по алфавиту, внутри — свежие сверху. Алфавит по кириллице — та же JS-функция:
   `sort_ru` (нижний регистр, `ё → е`), иначе «Ёжик» уехал бы после «Яна». «По рейтингу»
   появится вместе с оценками.
8. **Фильтр по автору** — выпадающий список авторов, у которых есть опубликованные
   посты, по алфавиту. В URL — id.
9. **Фильтр по периоду**: всё время (по умолчанию), неделя, месяц, год — по дате
   создания поста, отсчёт от текущего момента.
10. **Сортировка, автор и период — выпадающие списки** с видимыми подписями. Выбор сразу
    переходит по новому URL.
11. **Неизвестные значения игнорируются**: битая ссылка открывает ленту, а не ошибку.
    Несуществующий автор, неизвестная сортировка или период — как не заданные.

### Бесконечная прокрутка

12. **Порции по 20.** Первая рендерится сервером, следующие — server action, когда
    невидимая полоса в конце списка попадает в экран (`IntersectionObserver`).
13. **Сколько загружено — в URL**: после догрузки адрес тихо меняется на `?limit=40`
    (`router.replace` без прокрутки, история не набивается). По «назад» из поста сервер сразу
    отдаёт 40 постов, браузер восстанавливает прокрутку. `limit` — от 20 до 200, кратно
    20; больше 200 ссылкой не запросить, дальше догрузка идёт как обычно.
14. **Порция берётся по смещению**, дубли по id отбрасываются на клиенте: если между
    порциями опубликуют пост, список сдвинется на одну позицию, и последний пост прошлой
    порции придёт снова.
15. **Счётчик от сервера**: «Показано 40 из 132». Конец списка ничем не отмечен — счётчик
    уже всё сказал.
16. **Во время догрузки** — индикатор в конце списка. **Ошибка** — «Не удалось загрузить»
    и кнопка «Повторить»; загруженное остаётся.
17. **Любое изменение условий сбрасывает список** к первой порции: новый URL без `limit`.

## 3. URL

| параметр | значения | по умолчанию |
|---|---|---|
| `search` | строка | — |
| `sort` | `new`, `old`, `author` | `new` |
| `author` | id пользователя | все |
| `period` | `week`, `month`, `year` | всё время |
| `tag` | слаг, повторяется | — (спека 04) |
| `limit` | 20…200, кратно 20 | 20 |

Значения по умолчанию в URL не пишутся.

## 4. UI `/posts`

Сверху вниз:

1. Заголовок.
2. Поиск: поле и кнопка «Найти»; при активном поиске — крестик, снимающий только поиск.
3. Блок управления: «Сортировка», «Автор», «Период».
4. Ряд рубрик (спека 04) — ссылки сохраняют остальные условия.
5. Счётчик «Показано X из N» или, при поиске, «Найдено N».
6. Карточки и догрузка.

Пусто при любых условиях — «Ничего не нашлось» и «Сбросить всё» (ведёт на `/posts`).
Переключатель «Карточки / Таблица» убирается вместе с `PostList`: таблицы нет,
переключатель ничего не менял. Ленту рисует `FeedList`.

## 5. Вне scope

- Подсветка совпадений.
- Поиск на других страницах (главная, страница автора).
- Произвольный диапазон дат.
- Живое появление новых постов.
- Сортировка по рейтингу — вместе с оценками.

## 6. Отклонения от спеки

- **URL после догрузки — `router.replace`, а не `history.replaceState`.** Проверка нашла:
  по «назад» из поста лента возвращалась к 20 постам. `replaceState` меняет только адрес,
  а Next по «назад» берёт дерево из клиентского кэша — там первая порция. После
  `router.replace` кэш для этой записи истории — уже вся загруженная лента. Цена — лишний
  серверный рендер на порцию; при потолке 200 постов это допустимо. Состояние списка не
  сбрасывается: его `key` от `limit` не зависит.
- **Счётчик «Показано X из N» — в `FeedList`**: только он знает, сколько загружено сейчас.
- **Несуществующий автор сбрасывается до загрузки ленты**, а не после: иначе лента
  приходила пустой.
