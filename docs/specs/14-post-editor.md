# 14. Визуальный редактор текста поста

| | |
|---|---|
| Статус | done |
| Lifecycle | не меняется: правка текста — как была, только в `draft` |
| Источник идеи | next-2, спека 17 «Rich text» (`@mdxeditor/editor`) — взяты редактор, состав панели и решения по теме |
| Пересматривает | [08](08-post-markdown.md), п. 5 «редактор — поле с предпросмотром» |

## 1. Цель

Автор пишет пост в визуальном редакторе: жирный, заголовок, список видны сразу, разметку
знать не нужно. В БД по-прежнему markdown, страница поста рендерит его как раньше.

## 2. Решения

1. **`@mdxeditor/editor`, как в next-2.** Значение — строка markdown, ровно то, что лежит в
   `content`: миграции нет, рендер `PostMarkdown` (спека 08) не меняется.
2. **Панель — как в next-2**: жирный, курсив, стиль абзаца (текст, заголовок, подзаголовок,
   цитата), маркированный и нумерованный список, ссылка, разделитель, отмена и повтор.
   Подчёркивания, кода, таблиц и картинок нет: их нет и в рендере (картинки) или в
   markdown (подчёркивание).
3. **Заголовки — уровни 1 и 2 с подписями «Заголовок» и «Подзаголовок».** Отличие от
   next-2 (там 2 и 3): наш рендер сдвигает уровни вниз (`#` → `h2`, спека 08), и «Заголовок 2»
   из редактора стал бы `h3` на странице. В поле они оформлены так же, как на странице
   (`h2` / `h3` из `.ui-prose`).
4. **Поле оформлено стилями страницы поста** (`.ui-prose` на редактируемой области) —
   иначе это не WYSIWYG.
5. **Тема — наши токены.** Библиотека красится своими переменными `--base*` и в тёмной
   теме остаётся светлой; выпадающие списки и диалог ссылки рисуются в портале, вне
   формы. Переменные переопределяются на токены `tokens.css` для редактора и порталов
   (селекторы по подстроке класса, как в next-2).
6. **Диалог ссылки — по центру поля**, а не вплотную к кнопке (решение next-2: Radix
   позиционирует его inline-стилем, поэтому пересчёт в компоненте).
7. **Подписи на русском** — словарь `translation` из next-2, плюс подписи уровней из п. 3.
8. **Текст, который редактор не разобрал** (картинка, блок кода, сноска, JSX), — вместо
   редактора прежнее поле с предпросмотром (`PostMarkdownField`) и предупреждение «Текст
   не открылся в визуальном редакторе — правьте разметку». Текст не теряется.
9. **Грузится только в браузере и только в форме**: `dynamic(..., { ssr: false })`,
   заглушка той же высоты. Страницы чтения библиотеку не тянут.
10. **Шпаргалка и вкладка «Предпросмотр» уходят** из обычного режима: редактор сам
    показывает результат. Остаются только в запасном поле (п. 8).
11. **Редактор нормализует markdown при сохранении** (экранирует `*` и `_`, приводит
    списки к одному виду): вид поста тот же, строка в БД может измениться при первом
    сохранении. Поиск ленты ищет по сырой строке (спека 08), поэтому слово с
    экранированным символом внутри может перестать находиться — принимаем.

## 3. UI

Форма поста: поле «Текст» — редактор с панелью сверху, минимальная высота ~12 строк.
Ошибка поля — под редактором, как у остальных полей.

## 4. Вне scope

Режим «исходник» по кнопке, вставка картинок, таблицы, код, счётчик символов, правка
модератором, редактор в других формах (комментариев пока нет, «О себе» — простой текст).

## 5. Что показала проверка

- **Что редактор не разбирает** (проверено на черновиках): картинка `![]()`, блок кода
  (```), сноска, JSX — запасное поле. Сырой HTML и HTML-комментарий редактор открывает:
  текст показывает, теги сохраняет как есть, а `<script>` — с экранированием. Рендер их
  всё равно пропускает (`skipHtml`, спека 08). Таблица GFM открывается как простой текст и
  сохраняется без изменений.
- **Подписи для скринридера**: поле и группа списков подписаны по-английски (`editable
  markdown`, `toggle group`) — ключи `contentArea.editableMarkdown` и `toolbar.toggleGroup`
  добавлены в словарь. Кнопки панели подписаны `aria-label`, не `title`.
- **Плейсхолдер редактора** — отдельный узел с тем же `contentEditableClassName`: в тестах
  поле — `[contenteditable].ui-editor__content`.
- Двойной Enter после цитаты оставляет в markdown лишние пустые строки — на вид поста не
  влияет.
- Регрессия `markdown.cjs` переписана: markdown руками в визуальный редактор не вводится,
  поэтому текст кладётся в БД, а предпросмотр проверяется в запасном поле.
