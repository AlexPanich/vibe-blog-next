# 04. Рубрики постов

| | |
|---|---|
| Статус | done |
| Lifecycle | `docs/lifecycles/post.md` — рубрики как часть содержимого поста |
| Источник идеи | next-2, спека 18 «Теги постов и фильтрация ленты» — взята задача, не реализация |

## 1. Цель

У поста появляются рубрики из закрытого справочника, у читателя — фильтр ленты по ним.
Справочник ведёт модерация: автор выбирает из готового списка и не придумывает рубрики
на ходу, иначе через месяц в ленте пять одинаковых рубрик с разным написанием.

## 2. Решения

1. **Справочник ведут `moderator` и `admin`** в `office/moderation/tags`. У нас `admin`
   уже имеет все права модератора (`moderatePosts`), так что это функция раздела
   «Модерация», а не новое действие на две роли. Пункт «Рубрики» в группе «Модерация»
   меню.
2. **Рубрики — часть содержимого поста**: меняются в форме поста вместе с текстом и
   только в `draft`. Значит, проходят модерацию: модератор видит рубрики в очереди и
   при неподходящих отклоняет с комментарием. Отдельного правила для рубрик нет —
   действует то же «правка только в черновике».
3. **Удаление рубрики снимает её с постов**, посты остаются. Подтверждение называет
   последствие: «Рубрика снимется с N постов». Это меняет опубликованные посты без
   модерации, но только в части справочника, который модерация и ведёт.
4. **Слаг собирается из названия транслитерацией** при создании и **не меняется** при
   переименовании — старые ссылки на фильтр продолжают работать. Совпадение слагов —
   суффикс `-2`, `-3`. Транслитерация — переносимый хелпер в `core/`.

### Взято из next-2 без обсуждения — проверить

5. **До трёх рубрик на пост**, ноль тоже можно.
6. **Название** 2–30 символов, уникально без учёта регистра.
7. **Фильтр — мультивыбор с логикой «И»**: выбраны «Горы» и «Советы» — посты с обеими.
   Состояние в URL: `/posts?tag=gory&tag=sovety`.
8. **Счётчики в фильтре** — число опубликованных постов. Рубрики с нулём в ряд не
   попадают, кроме уже выбранных: иначе после снятия последнего поста фильтр нечем
   выключить. Нет ни одной рубрики с постами — ряда нет вовсе.
9. **Неизвестный слаг в URL игнорируется**, лента фильтруется по остальным. Битая ссылка
   открывает ленту, а не пустой список. (В next-2 — пустой список.)
10. **Порядок рубрик — по алфавиту** везде: в фильтре, в форме, в справочнике.

## 3. Данные

- `tags`: `id`, `name`, `nameKey` (unique — название в нижнем регистре), `slug`
  (unique), `createdAt`.
- `post_tags`: `postId`, `tagId`, первичный ключ из обоих. Удаление рубрики снимает её с
  постов явно, в транзакции (см. отклонения). На `postId` cascade не нужен: постов не
  удаляют.

## 4. Домен

Новый домен `tags`: справочник, его actions и страница. Посты используют рубрики через
`tags/exports`: чип рубрики, ресурс, список для формы. Связь пост–рубрика пишет
`posts` — в своих actions создания и правки.

## 5. UI

### 5.1 Справочник: `/office/moderation/tags`

- Форма сверху: «Название» и «Добавить».
- Строки: название, слаг, число постов (всех статусов), действия «Переименовать» и
  «Удалить».
- Переименование — в строке: поле и «Сохранить» / «Отмена».
- Удаление — с подтверждением «Рубрика снимется с N постов».
- Пусто — «Рубрик пока нет. Авторы выберут их при написании поста».

### 5.2 Форма поста

Блок «Рубрики» после текста: чипы-переключатели, подпись «Выбрано 2 из 3». При трёх
выбранных остальные чипы неактивны, но не скрыты — список не прыгает. Рубрик нет —
«Рубрик пока нет — их заводит модерация».

### 5.3 Где видны рубрики

| место | вид |
|---|---|
| карточка в ленте | чипы-ссылки на `/posts?tag=…`, вне ссылки на пост |
| публичная страница поста | чипы-ссылки рядом с датой |
| кабинет автора, страница поста | чипы-подписи |
| очередь модерации и страница модерации поста | чипы-подписи (пост не опубликован, ссылка увела бы в пустую ленту) |
| «Все посты» в админке | чипы-подписи в строке |

Ряд чипов рисуется, только если рубрики есть.

### 5.4 Фильтр ленты `/posts`

Над лентой — ряд чипов «Все» и рубрики со счётчиками (решение 8). Клик — переход по
ссылке, повторный клик по активному снимает его, «Все» сбрасывает фильтр. Пусто при
фильтре — «По этим рубрикам постов пока нет» и «Сбросить фильтр». *Заменено спекой 05:
пустой результат при любых условиях — «Ничего не нашлось» и «Сбросить всё».*

Поиск, сортировка и пагинация ленты — следующая спека (05), фильтр по рубрикам войдёт
в неё как одно из условий.

## 6. Вне scope

- Свободный ввод рубрики автором.
- Отдельная страница рубрики, облако рубрик.
- Подписки на рубрики.
- Правка рубрик модератором на чужом посте.
- Автогенерация url поста из заголовка — отдельно, хотя хелпер транслитерации будет
  готов.

## 7. Отклонения от спеки

- **Уникальность названия — колонка `nameKey`, а не индекс по `lower(name)`.** `lower()`
  в SQLite меняет регистр только у ASCII: «Горы» и «горы» прошли бы оба. `nameKey`
  считается в JS (`toLocaleLowerCase('ru')`).
- **Удаление рубрики чистит `post_tags` само.** `PRAGMA foreign_keys` в проекте не
  включён, и `onDelete: cascade` из схемы не срабатывает. Касается любой будущей таблицы
  с cascade.
- **Лимит `TAGS_PER_POST` — в `tags/dto/tagRequests.ts`, а не в `TagPicker`.** Файл с
  `'use client'` отдал бы серверной zod-схеме client reference вместо числа.
- **Порядок рубрик — сортировкой в JS** (`localeCompare('ru')`): `ORDER BY` в SQLite
  сравнивает байты.
