# 25. Правка поста вне черновика

| | |
|---|---|
| Статус | done |
| Lifecycle | `post.md` — переходы, «Черновик» |
| Источник идеи | next-2, спека 28 «Правка поста вне черновика» |
| Зависит от | 01, 12, 16 (галерея), 20 (уведомления) |

## 1. Цель

Править можно только черновик. Чтобы исправить опечатку в опубликованном посте, автор
должен сам догадаться: «Снять с публикации» → «Изменить» → «Отправить на модерацию». Кнопка
«Изменить» у не-черновика — понятнее, если она честно говорит, что будет с постом.

## 2. Решения

По аналогии с next-2. П. 2, 8, 9 и вопросы §6 обсуждены с человеком, остальные — по аналогии:

1. **Правка по-прежнему только в черновике** — правило lifecycle не меняется, иначе правка
   обходила бы модерацию. Меняется путь: «Изменить» у поста не в черновике **сначала
   возвращает его в черновик** существующим переходом, потом открывает форму.
2. **Какие статусы:** `published` (`unpublish`), `moderating` (`withdraw`), `rejected`
   (`redraft`), `blocked` (`redraftBlocked`) и `hidden` — новым переходом
   `redraftArchived` (`hidden → draft`, автор), парой к `blockArchived`. После правки
   архивный пост проходит модерацию, а не возвращается в ленту сам.
3. **Подтверждение перед переходом** с текстом по статусу — что произойдёт, а не что
   запрещено:
   - `published`: «Пост вернётся в черновик и пропадёт из ленты, пока модератор не одобрит
     его снова. Оценки и комментарии сохранятся.»
   - `moderating`: «Пост вернётся в черновик и уйдёт из очереди модерации. Если модератор
     уже взял его на ревью, ревью снимется.»
   - `rejected` / `blocked`: «Пост вернётся в черновик — после правки отправьте его на
     модерацию снова.»
   - `hidden`: «Пост вернётся из архива в черновик. После правки он пройдёт модерацию, а не
     вернётся в ленту сразу.»
4. **Второго вопроса при сохранении нет** (в next-2 был): форма у нас работает только с
   черновиком, а сменившийся пока форма открыта статус уже даёт 409 «Пост уже не
   черновик».
5. **Галерея — так же**: отдельной кнопки нет, галерея правится в той же форме.
6. **Повторная публикация ничего не рассылает**: ни подписчикам (спека 20, п. 5), ни плашкой
   в ленте (спека 22, п. 6) — `publishedAt` ставится один раз, пост возвращается на своё
   место в ленте, а не наверх.
7. **`admin` на чужом посте** проходит тот же путь, что автор (он работает с постом как
   автор). Модератор посты не правит — как сейчас.
8. **«Вернуть в черновик» убрана**: у `rejected` и `blocked` она делала то же, что
   «Изменить», только без формы. «Снять с публикации» и «Отозвать» остаются — у них свой
   смысл без правки.
9. **Правка модератором — вне scope** (§6): модератор решает, а не правит.
10. **Статус — от клиента.** `editPostAction` получает статус, который видел автор, и
    выбирает переход по нему: статус сменился, пока открыт диалог, — 409, а не другой
    переход, о котором автора не спрашивали.

## 3. Данные

Новых таблиц нет. Новый переход `redraftArchived`. Переход и редирект на форму — один
action `editPostAction`, таблица «статус → переход» — `POST_EDIT_TRANSITIONS` в
`postStatuses.ts`.

## 4. UI

- Кабинет поста: «Изменить» у статусов из п. 2 открывает подтверждение, по «Править» —
  переход и редирект на `office/posts/[id]/edit`. В «Моих постах» кнопок нет (строки —
  ссылки), там ничего не меняется.
- Подсказки статусов, которые объясняли обходной путь («снимите с публикации», «отзовите»,
  «верните в черновик»), убраны — это теперь текст подтверждения.

## 5. Вне scope

Правка без возврата в черновик, версии и откат правки, правка поста модератором.

## 6. Закрытые вопросы

- **Архив → черновик** — новый переход `redraftArchived` (п. 2).
- **Правка модератором (next-2, 07 и 28 п. 4)** — нет, вне scope (п. 9).

## 7. Что показала проверка

Прогон в браузере за bob (посты 4 и 5 временно переведены в архив и блокировку, после
прогона все статусы возвращены): у `published` — «Изменить», «Снять с публикации», «В
архив»; у `hidden` — «Изменить», «Восстановить»; у `blocked` — только «Изменить»; у
`moderating` — «Изменить», «Отозвать»; у черновика — «Редактировать», как раньше. Во всех
четырёх статусах подтверждение с текстом статуса, «Править» — пост в `draft` и форма
правки. Статус сменили, пока открыт диалог, — «Статус поста уже изменился — обновите
страницу», пост не тронут. Всё сходится.

- П. 10 появился при реализации: первая версия выбирала переход по статусу из БД и молча
  переводила в черновик пост, который успел уйти в архив.
- Отдельный план не писался: изменения уложились в решения спеки.
