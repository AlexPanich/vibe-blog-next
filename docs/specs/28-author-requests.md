# 28. Заявка «стать автором»

| | |
|---|---|
| Статус | done |
| Lifecycle | `user.md` — роли, новый раздел «Заявка на роль автора» |
| Источник идеи | открытый вопрос спеки 27 |
| Зависит от | 02 (роли, журнал), 20 (уведомления), 27 (стартовая страница) |

## 1. Цель

Человек без роли `author` видит «роль выдаёт администратор», но не может об этом попросить.
Нужна заявка: человек пишет, о чём хочет писать, admin одобряет или отказывает с причиной.

## 2. Решения

П. 1, 3, 6, 9 обсуждены, остальные — по аналогии (роли — спека 02, задачи staff —
`post.submitted` спеки 20):

1. **Решает только admin** — роли у нас меняет только он. Раздел
   `office/admin/author-requests`, пункт меню «Заявки» в «Администрировании» с бейджем
   числа ожидающих. Свою заявку admin не рассматривает (`manageUser`).
2. **Подать может** вошедший без роли `author` — в том числе moderator и admin без неё.
   Не больше одной ожидающей заявки (частичный уникальный индекс).
3. **Текст обязателен**: «О чём хотите писать», 30–1000 символов.
4. **Статусы**: `pending → approved | rejected`. Пока заявка ждёт, автор может её
   отозвать — строка удаляется: истории у отозванной нет, паузы тоже.
5. **Одобрение** — одна транзакция: заявка `approved` (атомарно, `WHERE status =
   'pending'`, иначе 409 «Заявка уже рассмотрена»), роль `author` в `users.roles`, запись
   `role_granted` в журнал с комментарием «По заявке», уведомление `user.role_granted`.
   Права admin перепроверяются в транзакции, как в `userAdminActions`.
6. **Отказ** — причина обязательна (3–500), заявитель видит её у себя. Новую заявку можно
   подать через **7 дней** после отказа — защита от спама заявками.
7. **Роль выдали руками**, пока заявка ждёт (форма ролей в админке), — заявка
   закрывается как `approved` тем же admin. Роль потом сняли — можно подать снова, пауза
   действует только после отказа.
8. **Бан** заявку не трогает: в списке у неё пометка «заблокирован», решить можно.
9. **Уведомления**: admin-ам без бана — задача `author_request.created` (актор —
   заявитель), удаляется, когда заявку решили, отозвали или закрыли выдачей роли.
   Заявителю — `user.role_granted` при одобрении (ссылка на «Начало») и
   `author_request.rejected` при отказе (ссылка на страницу заявки). Причина в текст
   уведомления не входит — она на странице заявки.
10. **У заявителя**: карточка роли на `/office` показывает состояние — «Подать заявку»,
    «Заявка на рассмотрении», «Заявка отклонена: <причина>, новую можно подать с <даты>».
    Страница `office/author-request` — форма, текущая заявка с «Отозвать» и история
    рассмотренных. «Мои посты» без роли — кнопка «Подать заявку».
11. **У admin**: вкладки «Ожидают» (давние сверху) и «Рассмотренные» (50 последних).
    Строка — аватар и имя (ссылка в админку пользователя), дата регистрации, число
    комментариев, текст заявки, «Одобрить» и «Отклонить» с полем причины.

## 3. Данные

`author_requests`: `id`, `user_id`, `text`, `status` (`pending` | `approved` |
`rejected`), `reason`, `decided_by`, `decided_at`, `created_at`. Уникальный индекс
`user_id WHERE status = 'pending'`, индекс `(status, created_at)`. CHECK: отказ — с
причиной, решённая — с `decided_by` и `decided_at`.

Новые типы уведомлений `author_request.created`, `author_request.rejected` — только в TS
(колонка `type` без CHECK по списку).

## 4. UI

- `app/office/author-request/page.tsx` — заявитель.
- `app/office/admin/author-requests/page.tsx` — admin.
- Домен `users`: `authorRequestActions.ts`, `authorRequestAdminActions.ts`,
  `authorRequestRequests.ts`, ресурсы — в `userResources.ts`, компоненты
  `components/authorRequest/` — `AuthorRequestForm`, `AuthorRequestWithdraw`,
  `AuthorRequestRow`. Admin-транзакция вынесена из `userAdminActions.ts` в
  `shared/userAdminTransaction.ts` — ей пользуются оба файла actions.

## 5. Вне scope

Письма о решении, заявки на другие роли, комментарий admin при одобрении, переписка по
заявке.

## 6. Открытые вопросы

Нет.

## Отклонения при реализации

- Пункт меню — «Заявки», заголовок страницы — «Заявки в авторы».
- У заявителя причина отказа — в строке истории, а плашка сверху говорит только, с какой
  даты можно подать снова: иначе причина повторялась дважды.
- `user.role_granted` с ролью `author` ведёт на «Начало», остальные роли — в профиль, как
  раньше.
- На «Начале» карточка роли теперь есть у любого без `author`, поэтому ветка спеки 27
  «Первые шаги пройдены» убрана: читатель без роли всегда видит хотя бы её.
