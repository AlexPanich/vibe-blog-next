# 27. Первые шаги: пустые состояния кабинета

| | |
|---|---|
| Статус | done |
| Lifecycle | `user.md` — роли; `post.md` — модерация |
| Источник идеи | next-2, спека 29 «Онбординг: первый пост» |
| Зависит от | 02 (роли), 23 (комментарии к моим постам) |

## 1. Цель

После регистрации и входа человек попадает в `office/profile` без ролей: «Мои посты» в меню
ему не видны, писать он не может, и нигде не сказано почему. У самого `/office` страницы
нет — 404. Автор с пустым списком видит «Постов пока нет» и не знает, что пост пройдёт
модерацию. Пустые места должны объяснять следующий шаг.

## 2. Решения

По аналогии с next-2, п. 1 и 4 — свои; содержание `/office`, блок staff и пункт меню
обсуждены:

1. **Стартовая страница кабинета** (свои): `/office` — «Начало», туда же ведёт вход
   (пароль, GitHub, ссылка из письма верификации) вместо профиля и пункт «Кабинет» в
   меню пользователя. Чек-лист «С чего начать» по факту: без роли `author` — «Писать
   посты могут авторы — роль выдаёт администратор» (пока роли нет); автору без постов —
   «Начните с первого поста»; без подписок на авторов и рубрики — «Подпишитесь на
   авторов»; без аватара или «О себе» — «Расскажите о себе». Ниже у автора — 3 последних
   поста, «Новый пост» и «Все посты · N». Без формы заявки (§5).
   - moderator / admin — строка «На проверке: N · Жалоб: M» со ссылками в очереди.
   - Все шаги пройдены — у автора только его посты. Читателю без роли карточка роли видна
     всегда (с заявкой — спека 28), поэтому «Первые шаги пройдены» убрано.
   - В левом меню — «Начало» первым пунктом «Кабинета», активен только на `/office`.
2. **«Мои посты», пусто** — приглашение: «Начните с первого поста», «Пост уходит на
   проверку модератору — читатели увидят его после публикации. Пока пост в черновике, его
   видите только вы», кнопка «Написать первый пост». Кнопка «Новый пост» в шапке остаётся
   (next-2, 29 п. 4).
3. **Подсказка живёт по факту**: пока постов нет — без флага «уже показывали» (next-2).
4. **Общий компонент `EmptyState`** (свои): иконка, заголовок, пояснение, действие — на
   базе существующего `.ui-empty`. Переводим места «о себе»: «Мои посты», «Мои
   комментарии», «К моим постам», «Избранное», «Подписки» (все вкладки), «Сообщения»
   (все вкладки), «Моя лента» без подписок. Очереди
   модерации и админка — не трогаем: там пустота значит «работы нет», другой тон.
5. **Тексты** — что сделать, а не констатация: «Вы пока ничего не отложили — добавить в
   избранное можно кнопкой на странице поста».

Нет.

## 4. UI

- `components/general/EmptyState.tsx` — без пометок server/client: им пользуется и
  клиентский `DialogList`.
- `app/office/page.tsx` — «Начало»; вход (`authActions`, `LoginForm`) ведёт туда.
- Стили — `.ui-empty__*`, `.ui-steps`, `.ui-start-line` в `layout.css`.

## 5. Вне scope

Мастер «Далее», заявка на роль автора, подсказки на главной и в ленте (сессия там
читается только на клиенте), пустые состояния очередей и админки.

## 6. Открытые вопросы

Нет. Заявка «стать автором» — спека 28.

## Отклонения при реализации

- `EmptyState` не серверный, а универсальный: пустой список переписок рисует клиентский
  `DialogList`.
- «Моя лента» без подписок не было в списке п. 4 — переведена тоже, иначе выбивалась бы
  по виду. «Ничего не нашлось» в ленте остаётся как есть: это результат поиска.
- Смена email (`callbackURL`) и уведомления о ролях и аватаре по-прежнему ведут в
  профиль — там то, о чём они.
