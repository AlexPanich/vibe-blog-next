# 13. Типы постов

| | |
|---|---|
| Статус | done |
| Lifecycle | `docs/lifecycles/post.md` — тип как часть содержимого поста |
| Источник идеи | hw2: `POST_TYPES`, `postDetailsDto`, `posts_type_fields_check` — взяты модель и поля, правила под hw3 |

## 1. Цель

У поста появляется тип, и от типа зависят его поля: перевод ссылается на оригинал,
путешествие привязано к точке на карте. Читатель видит тип на карточке и выбирает его
вкладкой над лентой.

## 2. Решения

1. **Три типа, как в hw2**:

   | тип | метка | свои поля |
   |---|---|---|
   | `simple` | Обычный | — |
   | `translate` | Перевод | `source` — ссылка на оригинал, обязательна |
   | `travel` | Путешествие | `lat`, `lng` — координаты, обязательны |

   Значения в нижнем регистре, как статусы hw3 (`draft`, `published`), — они же идут в URL
   (`?type=travel`). Набор зашит в код: у типов разные поля, справочник в БД их не
   описал бы.
2. **Хранение — плоские nullable-колонки в `posts`** (`type`, `source`, `lat`, `lng`) и
   CHECK `posts_type_fields_check`, как в hw2: БД сама не даёт записать поле чужого типа
   или оставить пустым своё. Отдельные таблицы на три поля не окупаются.
3. **Существующие посты становятся `simple`** — default колонки, миграция без переноса
   данных.
4. **Тип — часть содержимого**: выбирается при создании и **меняется, пока пост
   черновик**, вместе с текстом и рубриками (правило «правка только в черновике», спека
   04). Отличие от hw2, где тип неизменяем: в hw3 после отправки на модерацию пост и так
   не правится, а в черновике незачем пересоздавать пост из-за ошибки в типе. При смене
   типа поля чужого типа обнуляются (`postDetailsColumns`), иначе запись отклонит CHECK.
5. **Модератор тип не правит** — видит тип и его поля в очереди и на странице модерации,
   одобряет или отклоняет. Неверный тип — причина отклонить с комментарием.
6. **Валидация — `z.discriminatedUnion('type', …)`** в `postOwnCreateDto`:
   - `source` — `http(s)://`, до 500 символов. Другие протоколы (`javascript:`) — ошибка
     поля: ссылка выводится как `<a href>`.
   - `lat` от −90 до 90, `lng` от −180 до 180, до 6 знаков после запятой.
7. **Вид**:
   - метка типа — в мета-строке карточки ленты, страницы поста, строки кабинета и
     модерации; у `simple` метки нет — иначе ею помечено почти всё;
   - перевод — ссылка «Оригинал» (`target="_blank" rel="noopener noreferrer nofollow"`);
   - путешествие — карта с меткой на странице поста (см. п. 11); в карточке ленты и
     строках — координаты текстом: десяток карт в ленте — тяжёлая загрузка.
8. **Лента — вкладки «Все · Обычные · Переводы · Путешествия»** над лентой, параметр
   `?type=`. Складываются с поиском, рубриками, автором, периодом и сортировкой;
   переключение вкладки сбрасывает загруженное число (`limit`), как смена любого
   фильтра. Неизвестный тип — «Все» (`catch`, как у прочих полей ленты). Пусто — общее
   «Ничего не нашлось».
9. **OpenGraph**: у перевода и путешествия над заголовком — метка типа.
10. Поиск ленты по `source` не ищет — только заголовок и текст, как раньше.
11. **Карта — Leaflet + `react-leaflet`**:
    - в форме — под полями координат: клик ставит метку, метку можно тащить; поля и
      карта синхронны в обе стороны, точку можно и ввести числами;
    - на странице поста — карта высотой ~300 px с меткой и ссылка «Открыть в
      OpenStreetMap»; колесо мыши не зумирует, пока карта не в фокусе, — иначе
      страница перестаёт прокручиваться;
    - тайлы OpenStreetMap без ключа, в тёмной теме затемнены CSS-фильтром (см. «Что
      показала проверка»); подпись «© OpenStreetMap» обязательна. Для продакшена с
      нагрузкой нужен провайдер с ключом, и URL тайлов тогда уезжает в `config/`;
    - Leaflet трогает `window` при импорте: компонент грузится через
      `dynamic(..., { ssr: false })`, на месте карты — заглушка того же размера, без
      расхождения гидрации (скил `hydration`);
    - метка — `CircleMarker` в цвете бренда, без картинок: стандартная иконка Leaflet
      ломается в бандле Next.

## 3. Данные

Миграция `0009_post_types`: `posts.type text not null default 'simple'`, `source text`,
`lat real`, `lng real`, CHECK на тип и согласованность полей. Индекс по `type` — для вкладок
ленты.

## 4. UI

- Форма поста (создание и правка черновика): `SegmentedControl` «Тип поста» над
  заголовком, под ним поля выбранного типа.
  У путешествия — карта выбора точки.
- Страница поста, карточка, `PostRow`: метка и поля типа; на странице поста у
  путешествия — карта.
- Лента: вкладки над поиском.

## 5. Вне scope

Поиск места по названию (геокодинг), карта в карточках ленты и общая карта всех
путешествий, иконки типов на странице автора, статистика по типам, свои правила
модерации для типа, правка полей модератором.

## 6. Что показала проверка

- **CARTO без ключа больше не работает**: вместо карты — тайлы «API KEY REQUIRED». Решено с
  человеком: тайлы OSM, в тёмной теме — `invert + hue-rotate` на слое тайлов; метка и
  кнопки в других слоях и фильтр не получают.
- **Сгенерированная миграция была нерабочей дважды**: drizzle-kit копировал в
  пересобранную таблицу ещё не существующие колонки, а имя `__new_posts` в CHECK ломало
  `RENAME`. Главное — пересборка `posts` в принципе невозможна: drizzle-kit ведёт
  миграцию в транзакции, `PRAGMA foreign_keys=OFF` там не действует, и `DROP TABLE posts`
  падает на ссылках из `post_tags`, `post_ratings` и прочих (`defer_foreign_keys` только
  переносит ошибку на COMMIT). Миграция `0009` написана руками: `ADD COLUMN`, CHECK — на
  колонке `lng`. `drizzle-kit migrate` при ошибке молча откатывается — причину показал
  только прогон migrator'а `drizzle-orm` на копии базы.
- Вкладки типов — тоже `nav.ui-filter`, но с подчёркиванием (`.ui-feed-types`), чтобы не
  спутать с чипами рубрик.
- Клик по карте за краем мира давал долготу за ±180 — точки нормализуются `wrap()`.
