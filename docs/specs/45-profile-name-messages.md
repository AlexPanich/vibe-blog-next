# 45. Профиль: смена имени и «Кто может мне писать»

| | |
|---|---|
| Статус | черновик — решения предложены, не обсуждены |
| Lifecycle | `user.md` — поля профиля; `message.md` — кто может начать диалог |
| Источник идеи | спека 42, «Не сделано»: поле «Имя» и три варианта в секции «Личные сообщения» |
| Зависит от | 11 (профиль), 21 (личные сообщения), 26 (блокировка), 42 (вид профиля) |

## 1. Цель

В макете профиля (`office/profile`):

- поле «Имя» в секции «Публичная страница» — сейчас имя задаётся при регистрации и
  поменять его нельзя;
- «Кто может мне писать» — три варианта: «Все», «Мои подписки», «Никто». Сейчас один
  флаг `messagesFriendsOnly` — «только друзья» (взаимные подписки).

## 2. Решения (предложены)

**Имя**

1. Своё action `updateNameAction` (better-auth `updateUser` не трогаем — `name` у него
   есть, но остальные поля профиля мы пишем сами). 2–40 символов, без пустых по краям.
2. Ограничение частоты: не чаще раза в сутки (rate limit по пользователю), чтобы имя не
   меняли ради выдачи себя за другого.
3. Запись в журнал не нужна (это не admin-действие).

**Кто может писать**

4. Заменить флаг на enum `messages_from`: `all` | `following` | `friends` | `nobody`.
   - `all` — любой (кроме заблокированных, спека 26);
   - `following` — те, на кого подписан я (в макете «Мои подписки»);
   - `friends` — взаимные (нынешний флаг) — оставить, чтобы не потерять поведение;
   - `nobody` — новые диалоги закрыты, существующие продолжаются.
   В макете три варианта — открытый вопрос, показывать ли четвёртый.
5. Staff по-прежнему обходит запрет (как сейчас с флагом).
6. Миграция: `messagesFriendsOnly = true` → `friends`, иначе `all`.

## 3. Данные

`users.messages_from text NOT NULL DEFAULT 'all'` с CHECK на колонке (`ADD COLUMN`),
данные переносятся из `messages_friends_only`, старая колонка удаляется отдельной
миграцией позже. Правила — `domains/messages/policy.ts`, `docs/lifecycles/message.md`.

## 4. UI

Профиль: поле «Имя» рядом с «О себе»; варианты — радио-карточки в ряд (десктоп) или
список с радио (телефон), как в макете «Кабинет — Профиль».

## 5. Вне scope

Смена email (уже есть), публичный ник/handle, история имён.

## 6. Открытые вопросы

- Варианты: три из макета (без «друзей») или четыре?
- Нужен ли лимит частоты смены имени и какой?
