# 15. Комментарии

| | |
|---|---|
| Статус | done |
| Lifecycle | новый `docs/lifecycles/comment.md`; `post.md` — комментарии опубликованного поста |
| Источник идеи | next-2, спеки 03, 08, 12, 13 — дерево, реакции, «мои комментарии», скрытие; правила под hw3 |

## 1. Цель

Читатели обсуждают пост: пишут комментарии, отвечают друг другу веткой, ставят лайк или
дизлайк. Автор правит и удаляет своё, модератор скрывает нарушения с причиной.

## 2. Решения

Обсуждены с человеком:

1. **Дерево ответов любой глубины**, как в next-2. Отступ растёт до 5-го уровня (на
   телефоне — до 3-го), глубже ответы идут без нового отступа с пометкой «→ имя» — кому
   ответили.
2. **Комментировать можно только `published` пост.** Пост ушёл из ленты — комментарии
   сохраняются и возвращаются вместе с ним (как оценки, спека 07). Проверка статуса — в той
   же транзакции, что запись.
3. **Свой комментарий правится в любое время** с пометкой «изменён» и **удаляется**:
   без ответов — совсем, с ответами — остаётся заглушка «Комментарий удалён» (текст
   стирается), чтобы ветка не развалилась.
4. **Модератор скрывает чужой комментарий с обязательной причиной**, может вернуть.
   Вместо текста — «Скрыт модератором», ответы на месте. Автор комментария видит свой текст
   и причину. Решения пишутся в журнал `comment_moderations` — по образцу блокировки
   постов (спека 01).
5. **Автор поста чужие комментарии не трогает** — иначе убирал бы критику.
6. **Лайк / дизлайк**, как в next-2: одна реакция на пару комментарий–пользователь,
   повторный клик снимает, другой — переключает. Счётчики видят все.
7. **«Мои комментарии» в кабинете** — свои комментарии со ссылками на посты, скрытые — с
   причиной. Скрывает и возвращает модератор прямо на странице поста.

Приняты по аналогии (проверить):

8. **Отдельный домен `comments`**; странице поста он отдаёт блок через `exports/`.
9. **Простой текст**, 1–2000 символов, переносы строк сохраняются, ссылки не кликабельны.
   Markdown в комментариях — повод для спама ссылками и вторая поверхность XSS.
10. **Порядок — по времени, старые сверху**, и для корней, и внутри ветки: обсуждение
    читается как разговор.
11. **Публичная часть сессию на сервере не читает** (как оценки, спека 07). Дерево
    рендерит сервер без скрытых текстов; после гидрации клиент догружает «своё»: свои
    реакции, текст и причину своих скрытых комментариев, а модератору — тексты всех
    скрытых. Так скрытый текст не попадает в HTML для всех.
12. **Нельзя**: реагировать на свой комментарий (как оценка своего поста); отвечать,
    реагировать и править скрытый или удалённый; модератору — скрывать и возвращать свой.
    Забаненный войти не может (спека 02), его комментарии остаются.
13. **Удаление чистит за собой**: комментарий без ответов удаляется вместе с реакциями,
    и если его родитель — заглушка «удалён», у которой больше нет ответов, удаляется и она
    (по цепочке вверх). `PRAGMA foreign_keys` выключен — всё явно в транзакции.
14. **Счётчик в заголовке блока** — «Комментарии · N» без удалённых. В карточке ленты
    счётчика нет — отдельная фича при надобности.
15. **Лимит** — 10 комментариев в минуту на пользователя (`consumeOrFail`), правка и
    реакции — без отдельного лимита, их держит глобальный лимит proxy.
16. **«Мои комментарии»** показывают только комментарии к опубликованным постам, свежие
    сверху (как избранное, спека 10). Удалённые не показываются.

## 3. Данные

- `comments`: `id`, `postId`, `userId`, `parentId` (null у корня), `content`, `createdAt`,
  `editedAt`, `deletedAt`, `hiddenAt`, `hiddenBy`, `hideReason`. Индексы по `postId` и
  `userId`. CHECK: скрытый — с причиной.
- `comment_reactions`: `commentId`, `userId`, `value` (CHECK `1` / `-1`), PK пары.
- `comment_moderations`: `id`, `commentId`, `userId`, `decision` (`hidden` / `unhidden`),
  `comment`, `createdAt`; CHECK: `hidden` — с комментарием. Записи не меняются.

## 4. UI

- Страница поста: блок «Комментарии · N» вместо заглушки `TmpCommentsForm`; форма нового
  комментария сверху; у комментария — имя автора (ссылка на страницу автора), дата,
  «изменён», текст, 👍 N 👎 N, «Ответить» (форма раскрывается под комментарием), у своего —
  «Изменить», «Удалить», у модератора — «Скрыть» (поле причины) / «Вернуть». Гость —
  «Войдите, чтобы комментировать».
- Кабинет: `office/comments` «Мои комментарии», пункт в группе «Кабинет».

## 5. Вне scope

Жалобы, уведомления об ответах, правка чужого модератором, счётчик в карточке ленты,
сортировка по рейтингу, пагинация (сразу всё дерево), упоминания, markdown, live-обновление.

## 6. Что показала проверка

- **Модератор возвращал свой скрытый комментарий.** Скрытие — решение о нём, и отменять его
  сам себе он не должен: `unhideComment` и `unhideCommentAction` требуют чужой комментарий.
- Отступ: «до 5-го уровня» — уровни 1–5 (корень — 0) сдвигаются, с 6-го — без сдвига и с
  «→ имя»; на узком экране — с 4-го.
- Лимит 10/мин копится между прогонами e2e: флуд в сценарии делает отдельный пользователь,
  иначе следующий прогон упирается в лимит автора.
