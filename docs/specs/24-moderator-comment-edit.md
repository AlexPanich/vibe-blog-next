# 24. Правка чужого комментария модератором

| | |
|---|---|
| Статус | done |
| Lifecycle | `comment.md` — кто что может, журнал |
| Источник идеи | next-2, спека 15 «Модераторская правка чужого комментария» |
| Зависит от | 15 (комментарии), 18 (жалобы), 20 (уведомления) |

## 1. Цель

Модератор может только скрыть комментарий целиком. Опечатку в ссылке, телефон, одно грубое
слово в длинном полезном ответе проще исправить на месте, чем прятать всё.

## 2. Решения

По аналогии с next-2, п. 4–6 — свои. П. 4 (стирание при удалении) и 9 обсуждены с человеком,
остальные — проверить:

1. **`moderator` и `admin` правят чужой видимый комментарий** на странице поста (и
   картинки) — кнопка «Изменить» рядом со «Скрыть», та же форма, что у автора.
2. **Скрытый не правится** — даже модератором: сначала «Вернуть», потом править (next-2).
   Удалённый («заглушка») — тоже нет.
3. **Свой комментарий модератор правит как автор**, обычной правкой.
4. **Журнал (свои).** Правка модератора пишется в `comment_moderations` решением `edited`
   с прежним текстом в `comment` — без этого после правки нельзя понять, что было написано
   на самом деле. В UI журнал не выводится (как и скрытия) — только в БД. **Удаление
   комментария автором стирает прежние тексты** в его записях `edited` (кто и когда —
   остаются): удаление обещает, что текста больше нет. То же — при удалении картинки с
   веткой.
5. **Пометка «изменён модератором»** у комментария вместо «изменён» (колонка
   `editedBy`); правка автором после этого снова пишет «изменён» и сбрасывает
   `editedBy`.
6. **Автору комментария — уведомление `comment.edited`** (спека 20): правка чужого текста
   без уведомления выглядела бы подменой.
7. **Открытые жалобы правка не закрывает**: модератор мог исправить не то, на что
   жаловались; разбор — отдельным решением (спека 18).
8. **Реакции, ответы, жалобы, скрытость** правкой не затрагиваются; меняются только текст,
   `editedAt` и `editedBy`. Проверка состояния — в том же UPDATE: устаревшая страница
   получает 409.
9. **Без причины правки.** Форма та же, что у автора; уведомление «Модератор изменил ваш
   комментарий к посту «…»» ведёт к комментарию — новый текст автор видит там.
10. **Один action.** `updateCommentAction` правит свой как автор, чужой — только staff (с
    журналом и уведомлением). Форма и кнопка общие, право — policy `editComment`.

## 3. Данные

- `comments.edited_by` — `ADD COLUMN`, nullable.
- `COMMENT_MODERATION_DECISIONS` += `edited`. Миграция таблицы не нужна: enum проверяется
  только в коде, CHECK `comment_moderations_hidden_comment` касается лишь `hidden`.
- `NOTIFICATION_TYPES` += `comment.edited`.

## 4. UI

- Страница поста: «Изменить» у чужого видимого комментария для staff.
- Метка «изменён модератором».

## 5. Вне scope

Правка из очереди жалоб, «показать оригинал» читателям, откат правки, правка скрытого.

## 6. Что показала проверка

Прогон в браузере (some — moderator, bob — автор, гость; тестовые комментарии к посту alice,
после прогона удалены): у some на чужом видимом — «Изменить» и «Скрыть» без «Удалить», на
чужом скрытом — только «Вернуть», на своём — «Изменить» и «Удалить»; правка some — метка
«изменён модератором» у всех, включая гостя, `edited_by`, запись `edited` с прежним текстом и
`comment.edited` у bob; у bob на своём — «Изменить» и «Удалить», на чужом — нет; правка bob —
снова «изменён», `edited_by` сброшен; удаление bob — запись журнала осталась, текст `NULL`,
уведомление удалено; правка из формы, открытой до скрытия, — «Комментарий скрыт
модератором — править нельзя», текст не изменился. Всё сходится.

- Одинаковый текст ничего не пишет: ни журнал, ни уведомление, ни `editedAt`.
- Метка «изменён модератором» — и во вкладке «К моим постам» (спека 23).
- Стирание текста — `eraseEditedTexts` в `commentGuards.ts`, наружу — через
  `comments/exports` (удаление картинки в домене `posts`).
- Не проверено вручную: стирание текста при удалении картинки с веткой (картинку удаляют
  только в черновике, а комментарии бывают только у опубликованного — сценарий долгий).
