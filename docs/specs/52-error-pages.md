# 52. Страницы ошибок

| | |
|---|---|
| Статус | done (без плана: задача — набор файлов-соглашений Next) |
| Lifecycle | не затрагивает |
| Макет | Pencil, фреймы «Ошибка … » и «Глобальная …» под экранами спеки 42, компонент `Error State` |
| Зависит от | 30, 42 (вид публичной части и кабинета) |

## 1. Цель

В `src/app` не было ни одного `not-found`, `forbidden`, `unauthorized`, `error` и `global-error`:

- `notFound()` в публичной части — шапка и подвал, а в середине английская заглушка Next;
- несуществующий адрес (`/nope-page`, `/office/nope`) — голая белая страница без темы;
- 404 и 403 в кабинете — голая страница без меню: `app/office/layout.tsx` — root layout, выше
  него границ нет;
- падение рендера — стандартная заглушка Next.

## 2. Решения

1. **Общий вид** — `components/general/ErrorScreen.tsx` (без пометок server/client: его
   рисуют и серверные границы, и клиентские). Плитки с кодом цветов типов постов (коралл,
   солнце, слива, повёрнуты), надзаголовок, заголовок, пояснение, кнопки слотом. Без кода —
   одна солнечная плитка «!» (сбой рендера). Классы — `.ui-error*` в `layout.css`, цвета из
   токенов. `.ui-empty` / `EmptyState` не подошли: это строка внутри списка, а здесь — вся
   страница.
2. **Следующий шаг** — тёмная кнопка (`.ui-ink-button`) и светлая (`variant="default"`):

   | граница | заголовок | кнопки |
   |---|---|---|
   | `(public)/not-found` | Такой страницы нет | В ленту · На главную |
   | `(public)/forbidden` | Сюда нельзя | гость: Войти · В ленту; вошедший: В ленту · На главную |
   | `(public)/error` | Что-то пошло не так | Попробовать ещё раз · В ленту |
   | `office/not-found` | Такой страницы нет | В кабинет · Мои посты |
   | `office/forbidden` | Нет доступа | В кабинет · Контакты |
   | `office/error` | Что-то пошло не так | Попробовать ещё раз · В кабинет |
   | `global-not-found` | Такого адреса нет | В ленту · На главную |
   | `global-error` | Что-то пошло не так | Попробовать ещё раз · На главную |

   Границы в `app/(public)/` и `app/office/` рисуются внутри своего root layout: шапка и
   подвал, в кабинете — его меню. Заголовок вкладки — React `<title>` (metadata у вложенных
   границ и у клиентских не поддерживается).
3. **`retry()`, а не `reset()`.** В Next 16.3 `retry` стал стабильным, документация советует
   его: он заново запрашивает серверные данные, `reset()` перерисовал бы тот же ответ.
4. **`unauthorized.tsx` не нужен.** `unauthorized()` вызывает только `breakIfCant` без
   пользователя. В публичной части page `breakIfCant` не зовут, в кабинете пользователь есть
   всегда — layout без него делает redirect на вход. `forbidden()` в публичной части сейчас
   тоже никто не вызывает: `(public)/forbidden.tsx` — граница на будущее, как и просили.
5. **`global-not-found.tsx`** (флаг `experimental.globalNotFound` в `next.config.ts`) —
   адреса вне маршрутов. По документации Next 16 файл обходит layout'ы, сам отдаёт `<html>`
   и `<body>`, сам подключает стили, шрифты и тему. Токены ссылаются на переменные
   `--mantine-color-*`, поэтому нужен `MantineProvider` — берём `ClientSideInitializer`, как в
   layout'ах. Шапка упрощённая: бренд, меню, тема — без поиска и пользователя (адрес мог
   прийти из любой части). Подвал — общий `SiteFooter`, нижней панели телефона нет.
6. **`global-error.tsx`** — упал сам root layout. Свой документ, `MantineProvider` с темой и
   шрифтами, без `ClientSideInitializer` (сессия и живой канал могли быть причиной падения).
   Колонка по центру экрана (`.ui-error-page`) с брендом. «На главную» — обычный `<a>`:
   полная перезагрузка, а не клиентский переход в упавшее дерево.
7. В dev на страницах после `notFound()` / `forbidden()` в консоли «Encountered a script tag
   while rendering React component» (скрипт темы Mantine в `<head>`) — особенность dev-режима
   Next, в production её нет. Не чиним.

## 3. Проверка

Браузер (субагент, скил `app-run`), гость и bob, светлая и тёмная, 1440 и 375 (без
горизонтального скролла); `/posts/99999999` и `/nope-page` — ещё и в production (`next start`).
`error` и `global-error` проверены временными страницами, которые бросали исключение
(удалены). `tsc`, `lint`, `build` — чисто.

| адрес | результат |
|---|---|
| `/posts/99999999` | 404 «Такой страницы нет», шапка и подвал |
| `/nope-page` | 404 «Такого адреса нет» (global-not-found), упрощённая шапка, подвал |
| `/office/nope`, гость | redirect на `/auth/login` (proxy) |
| сбой рендера в публичной части | 500 «Что-то пошло не так», «Попробовать ещё раз» снова рисует границу |
| сбой root layout | 500, `global-error` без шапки; в dev его закрывает оверлей Next |
| `/office/posts/<чужой>`, bob | 403 «Нет доступа» в меню кабинета |
| `/office/moderation/posts/<id>`, bob | 403 «Нет доступа» в меню кабинета |
| `/office/nope`, bob | 404 «Такого адреса нет» — global-not-found, без меню кабинета |
| сбой рендера в кабинете | 500 «Что-то пошло не так» в меню кабинета |

**Отклонения и открытые вопросы**

- Неизвестный адрес внутри кабинета (`/office/nope`) показывает глобальную 404, а не
  кабинетную: адрес не совпал с маршрутом, и Next не доходит до `office/layout.tsx`.
  Кабинетную 404 дал бы catch-all `office/[...missing]/page.tsx` с `notFound()`, но он
  делает любой `/office/*` валидным для `typedRoutes`. Не добавлен.
- Чужой пост в кабинете (`/office/posts/<id>`) — 403 (`breakIfCant(workWithPost)`), а не 404.
  Lifecycle про кабинетную страницу чужого поста ничего не говорит; поведение не менял,
  текст 403 общий («нет прав на эту страницу»), без упоминания ролей.
- `global-error` рендерит `ColorSchemeScript` из клиентского компонента — в dev то же
  предупреждение «Encountered a script tag» (п. 7). Скрипт нужен при серверном рендере
  границы, чтобы тема не мигала.
