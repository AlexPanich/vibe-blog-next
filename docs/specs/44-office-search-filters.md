## 1. Цель

В макете кабинета на нескольких страницах есть поиск и вкладки, которых в коде нет.
Новых таблиц не нужно — только параметры URL и запросы.

|---|---|---|
| ~~Мои посты~~ | ~~вкладки по статусам с числами, поиск по заголовку, пагинация~~ | сделано в спеке 42, шаг 3 |
| Уведомления | вкладки Все / Посты / Комментарии / Подписчики с числами | один список |

| Админ — Все посты | поиск по заголовку или автору | вкладки по статусу |
| Админ — Пользователи | вкладки Все / Авторы / Модераторы / Заблокированные, поиск по имени или email | фильтр все / заблокированные |

## 2. Решения (предложены)

1. Всё состояние — в `searchParams` (`?status=`, `?q=`, `?type=`, `?tag=`, `?sort=`,
   `?page=`), разбор — zod-dto домена с `.catch()`, как `postFeedFilterDto`.
2. Поиск — `lower_ru(...) LIKE lower_ru(?)` (функция уже есть в `globals/db.ts`), поле
   поиска — GET-форма, отправка по Enter и с задержкой 300 мс на клиенте.
3. Числа на вкладках — один `GROUP BY` по полю вкладки.
4. Уведомления: группа вкладки — по типу (`post.*` → «Посты», `comment.*` → «Комментарии»,
   `user.followed` → «Подписчики», остальное — только во «Все»). Маппинг — константа в
   домене `notifications`.
5. Избранное: вкладки — рубрики, которые есть у отложенных постов (не больше 6, остальные —
   «ещё»), сортировка — по дате добавления / по дате поста.
6. Пользователи: вкладка роли — `roles LIKE '%"author"%'` (роли хранятся JSON-строкой),
   «Заблокированные» — `bannedAt IS NOT NULL`.
7. Пагинация — по 20, ссылки «1 2 →» (макет «Мои посты»).

## 3. Данные

Новых полей нет. Возможно, индекс `notifications (user_id, type, created_at)`.

## 4. UI

Вкладки-пилюли и поле поиска — общий вид из спеки 42 (п. 3). На телефоне вкладки —
прокручиваемые чипы.

## 5. Вне scope

Полнотекстовый поиск (FTS5), поиск по тексту постов, сохранённые фильтры.
