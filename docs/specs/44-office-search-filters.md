## 1. Цель

Новых таблиц и полей не нужно — только параметры URL и запросы.

## 2. Решения

### Общее

1. Всё состояние — в `searchParams` (`?q=`, `?tab=`, `?role=`, `?tag=`, `?sort=`, `?page=`),
   разбор — zod-dto домена с `.catch()`, как `postAdminFilterDto` / `userAdminFilterDto`.
   Ссылки — url-хелперы домена (`adminPostsUrl`, `adminUsersUrl`, новые `notificationsUrl`,
   `favoritesUrl`), значения по умолчанию в URL не пишутся.
2. **Поиск — обычная GET-форма, отправка по Enter, без JS и без задержки** (обсуждено).
   Три существующие копии (`MyPostsSearch`, `TagSearch`, `AuthorsSearch`) сводятся в один
   общий компонент `components/general/OfficeSearch.tsx`: `action`, `q`, `placeholder`,
   `aria-label`, скрытые поля (`hidden: Record<string, string | undefined>`), ссылка сброса,
   класс-модификатор обёртки. Старые компоненты удаляются, места вызова переходят на общий.
3. Сравнение без регистра — `lower_ru(col) LIKE ? ESCAPE '\'` с `escapeLike` и
   `toLocaleLowerCase('ru')`, как `titleLike` в `loadMyPosts.ts`. Если хелпер нужен второму
   домену — поднять в корневой `shared/`.
4. Числа на вкладках **учитывают поиск** (как в «Моих постах»): один `GROUP BY` по полю
   вкладки с тем же `WHERE`, что у списка. Число в подзаголовке страницы — без поиска.
5. Смена вкладки сохраняет `q`, сбрасывает `page`. Отправка поиска сохраняет вкладку,
   сбрасывает `page`.

### Уведомления

6. **Вкладки: Все / Посты / Комментарии / Подписчики, у staff (moderator, admin) ещё
   «Модерация»** (обсуждено). Маппинг типа на вкладку — константа
   `NOTIFICATION_TABS` в `domains/notifications/shared/notificationTabs.ts`:

   | вкладка | типы |
   |---|---|
   | Посты | `post.approved`, `post.rejected`, `post.blocked`, `post.unblocked`, `post.published`, `post.featured`, `post.rated` |
   | Комментарии | `comment.created`, `comment.reply`, `comment.edited`, `comment.hidden`, `comment.unhidden` |
   | Подписчики | `user.followed` |
   | Модерация (staff) | `post.submitted`, `report.created`, `post_report.created`, `author_request.created` |
   | только «Все» | `message.created` (у сообщений свой раздел со счётчиком), `report.resolved`, `post_report.resolved`, `user.unbanned`, `user.role_granted`, `user.role_revoked`, `user.avatar_removed`, `user.cover_removed`, `author_request.rejected` |

   Новый тип в `NOTIFICATION_TYPES` должен попасть в маппинг: тип константы —
   `Record<NotificationType, Tab | null>`, пропуск ломает `tsc`.
   `?tab=moderation` у не-staff прижимается к «Все» в dto-разборе на странице.
7. **Число на вкладке — непрочитанные** (обсуждено); вкладка без непрочитанных — без
   числа. Считаются одним `GROUP BY type` по непрочитанным, суммируются в JS по маппингу.
   Группа спеки 51 — одна строка, считается за 1.
8. Подгрузка «ещё» (`loadNotificationsAction`, `beforeId`) получает вкладку и фильтрует
   `type IN (...)`. Индекса `(user_id, id)` хватает: хвост — 200 строк на получателя,
   новый индекс не нужен.
9. Живой канал: `notification.created` на открытой вкладке добавляет строку, только если
   её тип относится к вкладке; числа вкладок пересчитываются в любом случае (событие несёт
   тип). «Прочитать все» на вкладке читает только её уведомления; на «Все» — все, как
   сейчас. Колокольчик не меняется.

### Избранное

10. **Вкладки по рубрикам + сортировка** (обсуждено). Вкладки — до 6 рубрик, самых
    частых среди опубликованных отложенных постов (при равенстве — `localeCompare('ru')`),
    остальные — в «Ещё ▾». Компонент «Ещё» обобщается из `PostStatusMoreTab` (пункты:
    подпись, href, число). `?tag=` — slug рубрики; неизвестный slug — «Все».
11. Пост с несколькими рубриками есть в каждой своей вкладке, поэтому сумма чисел вкладок
    может быть больше «Все» — это ожидаемо.
12. Сортировка `?sort=` — `added` (по дате добавления, по умолчанию, как сейчас) или
    `published` (по дате публикации поста). Переключатель — `SegmentedControl` или две
    ссылки-чипа рядом с вкладками; выбор — план. Пагинации по-прежнему нет.
13. Подзаголовок («N отложенных постов — видно всем / видите только вы») — без изменений.

### Админ — Все посты

14. Поиск `?q=` — по заголовку поста **или** имени автора (`lower_ru` по обоим полям,
    join `users`). Вкладки статусов и «Ещё ▾» — как сейчас, числа с учётом поиска.

### Админ — Пользователи

15. Вкладки `?role=`: Все / Авторы / Модераторы / Заблокированные (как в макете).
    Роль — `roles LIKE '%"author"%'` / `'%"moderator"%'` (роли — JSON-строка).
    Админов отдельной вкладкой нет, они во «Все». «Заблокированные» — **только
    `banActiveSql(now)`** (спека 46), голую проверку `bannedAt` не писать. Параметр
    `?filter=banned` заменяется на `?role=banned`.
16. Поиск `?q=` — по имени или email (`lower_ru` по обоим). Пагинация — `Pager`, по 20.

## 4. UI

Вкладки — `.ui-tabs` с `.ui-tabs__count` и короткими подписями для телефона
(`ui-tabs__label-full` / `-short`), как на «Все посты». Поле поиска — `.ui-search`
из спеки 42. На телефоне вкладки — прокручиваемые чипы (уже так у `.ui-tabs`).
Пустой результат поиска — `.ui-empty` «Ничего не нашлось» со ссылкой «Сбросить поиск».

## 5. Вне scope

Полнотекстовый поиск (FTS5), поиск по тексту постов, сохранённые фильтры, пагинация
избранного, поиск в уведомлениях и избранном.

## 7. Проверка (2026-11-10)

`tsc` и `lint` чистые, старых имён (`MyPostsSearch`, `TagSearch`, `AuthorsSearch`,
`PostStatusMoreTab`, `filter=banned`, `ui-tag-bar__sort`) в `src` нет. В браузере (скил `app-run`)
пройден весь чек-лист плана: «Все посты» (поиск по заголовку и автору в другом регистре, числа
вкладок с поиском, подзаголовок без), «Пользователи» (4 вкладки, `?role=banned` без истёкших
банов, поиск по имени и email, `?filter=banned` → «Все», «назад» → `?role=banned`), уведомления
(«Модерация» только у staff, числа = непрочитанные, «Показать ещё» и «Прочитать все» по вкладке,
живой канал добавляет строку только на своей вкладке), избранное (6 рубрик + «Ещё ▾», `?tag=nope`
→ «Все», сортировка сохраняет вкладку), регрессия поиска на `/authors`, `/office/moderation/tags`,
`/office/posts`, ширина 390px. Ошибок консоли и hydration нет. Отклонений от решений нет.

Замечания, не баги спеки 44:

- **Подписка влезает в группу (спека 51).** Пока есть непрочитанная группа «Новый подписчик»,
  новая подписка обновляет её строку, а не добавляет — число «Подписчики» не растёт; это
  правильно (реш. 7: группа — 1). После отписки группа продолжает называть отписавшегося последним
  актором, повторная подписка уведомления не даёт (throttle) — вопрос к спеке 51.
- **Нули на вкладках.** «Мои посты» скрывают вкладки статусов с нулём (кроме активной), «Все
  посты» в админке показывают нули. Так было и до спеки 44; не выравнивали.
