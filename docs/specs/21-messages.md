# 21. Личные сообщения

| | |
|---|---|
| Статус | done |
| Lifecycle | новый `docs/lifecycles/message.md` — диалог, сообщение, кто может писать |
| Источник идеи | next-2, спека 39 «Сообщения между пользователями» |
| Зависит от | 19 (друзья), 20 (уведомления) |

## 1. Цель

Написать человеку напрямую, а не комментарием под постом: комментарий — разговор с
постом и всеми читателями, личное сообщение — с человеком.

## 2. Решения

По аналогии с next-2. П. 6, 7, 13 и 16 обсуждены с человеком, остальные — проверить:

1. **Диалог один на пару, без групп** (next-2).
2. **Диалог создаёт первое сообщение**: пустых диалогов нет. «Написать» на странице
   автора ведёт на `office/messages/new?to=<id>` — шапка собеседника и поле ввода; после
   отправки — `router.replace` на `office/messages/[id]`. Если диалог уже есть — сразу
   туда.
3. **Простой текст 1–2000 символов**, переносы сохраняются, ссылки не кликабельны — как
   комментарии (спека 15).
4. **История — последние 50, «Показать более ранние»** по курсору `id`, а не по
   смещению: пока листаешь, новые сообщения сдвигали бы страницы (next-2).
5. **Удалить можно своё сообщение, полностью**, у обеих сторон, без заглушки: веток нет,
   держать нечего (next-2). Правки нет. Последнее сообщение удалено — диалог остаётся,
   если в нём есть другие, иначе удаляется.
6. **Staff переписку не видит и не модерирует.** В next-2 модератор удалял чужие
   сообщения — значит, читал их. Жалоб на сообщения нет; защита — п. 7 и 8.
7. **«Запретить писать»** — в шапке диалога и на странице автора: этот человек больше не
   может мне написать, история остаётся у обоих, у него вместо поля — «Пользователь
   ограничил сообщения». Связь односторонняя, снимается той же кнопкой, список — вкладка
   в `office/messages`. Блокировки пользователя (next-2, 23) у нас нет, это её узкая
   замена только для лички.
8. **«Только от друзей»** — переключатель в `office/profile`, флаг
   `users.messagesFriendsOnly`: писать могут только взаимные подписчики (спека 19).
   Закрытость диалога не хранится, а вычисляется — подписка меняется и личка открывается
   сама (next-2). `moderator` и `admin` флаг обходят, запрет из п. 7 — нет.
9. **Писать нельзя**: себе, забаненному («аккаунт заблокирован»), при запрете или
   закрытой личке. Причину показывают вместо поля ввода, кнопку «Написать» на странице
   автора тогда не рисуем. Проверка — в той же транзакции, что запись: устаревшая
   страница получает 409.
10. **Прочитанность — `messages.readAt`** у входящих. Открытие диалога отмечает все
    входящие прочитанными, кнопки «прочитать» нет (next-2). Непрочитанные — счётчик у
    строки списка и у пункта меню «Сообщения».
11. **Список — `office/messages`**: собеседник (аватар, имя), обрезок последнего
    сообщения, время, непрочитанные; свежие сверху, догрузка порциями по 20. Пусто —
    «Сообщений пока нет, написать можно со страницы автора».
12. **Уведомление `message.created` — одно на диалог**: пока есть непрочитанное
    уведомление по этому диалогу, новое не создаётся, у старого обновляется время.
    Открытие диалога отмечает его прочитанным. Удаление сообщения удаляет уведомление,
    если других непрочитанных нет.
13. **Живое обновление — SSE из спеки 20** (§4). Событие `message.created` приходит
    обоим участникам (отправителю — для других его вкладок) с сообщением и `dialogId`:
    открытый диалог дописывает его, список обновляет строку (обрезок, время, счётчик),
    пункт меню — счётчик непрочитанных. `message.deleted` убирает сообщение у обоих.
    После переподключения открытый диалог догружает сообщения новее последнего по `id`.
14. **Лимиты**: 30 сообщений в минуту и 20 новых диалогов в час на пользователя.
15. **Бан**: забаненный не входит, его диалоги остаются у собеседников, писать ему нельзя
    (п. 9). Удаления пользователей нет — каскада по диалогам не нужно.
16. **«Скрыть переписку» — игнор** (next-2): диалог уходит из списка и из счётчика
    непрочитанных в меню, `message.created` по нему не создаётся. Писать он не мешает ни
    мне, ни собеседнику, диалог открывается по прямой ссылке. Новое сообщение переписку
    в список не возвращает — вернуть можно той же кнопкой или во вкладке «Скрытые».
    Связь моя, а не диалога (`message_ignores`, не флаг на `dialogs`): у собеседника всё
    на месте, он об игноре не знает. Ставится и до первого сообщения, без подтверждения.
    С запретом из п. 7 независим. Лимит — 200.

## 3. Данные

- `dialogs`: `id`, `userLowId`, `userHighId` (CHECK `low < high`, уникальная пара),
  `lastMessageAt`, `createdAt`.
- `messages`: `id`, `dialogId`, `userId` (автор), `content`, `createdAt`, `readAt`;
  индекс `(dialogId, id)`.
- `message_restrictions`: `userId` (кто запретил), `restrictedId`, `createdAt`; PK пары.
- `message_ignores`: `userId` (кто скрыл), `ignoredId`, `createdAt`; PK пары.
- `users.messages_friends_only` — `ADD COLUMN`, по умолчанию выключен.
- `NOTIFICATION_TYPES` += `message.created`, `notifications.dialogId`.

## 4. UI

- `/authors/[id]`: «Написать» (после гидрации, гостю — вход), «Запретить писать».
- `office/messages` — список (у строки — «Скрыть переписку»), вкладки «Скрытые» и
  «Ограниченные» с кнопкой возврата в строке; `office/messages/[id]` — диалог: в шапке
  «Скрыть переписку» / «Вернуть в список» и «Запретить писать», свои справа, чужие
  слева, дата и время через `LocalDate`, у своего — «Удалить» с подтверждением, поле
  ввода внизу (`Enter` — отправить, `Shift+Enter` — перенос).
- Пункт «Сообщения» со счётчиком непрочитанных в группе «Кабинет».

## 5. Вне scope

Группы, вложения и картинки, правка сообщений, реакции, «печатает…», жалобы на
сообщения и доступ staff, поиск по переписке, письма.

## 6. Что показала проверка

Прогон в браузере (alice, bob, some): «Написать» со страницы автора → `new?to=` → первое
сообщение (Shift+Enter — перенос) → `router.replace` на диалог; у alice строка в списке,
счётчик в меню и уведомление появились без перезагрузки; открытие диалога обнулило оба;
ответ дошёл до bob в открытый диалог; удаление своего убрало сообщение у alice. Запрет со
страницы автора — у bob причина вместо кнопки и вместо поля ввода, вкладка
«Ограниченные», снятие. «Только от друзей» — bob видит причину, модератор some может
писать. Скрытие — строка ушла, новое сообщение bob не вернуло её и не дало уведомления,
вкладка «Скрытые», «Вернуть в список».

- **«У старого уведомления обновляется время» (п. 12) — заменой**: прежнее непрочитанное
  `message.created` удаляется и создаётся новое. Колокольчик сортирует по id, и только так
  свежая переписка поднимается наверх.
- **Событие `message.read`** (только себе) — сверх п. 13: открытый в одной вкладке диалог
  обновляет счётчик в меню других; скрытие переписки шлёт его с `dialogId: null`.
- **Пункт «Сообщения» — первым в группе «Кабинет» после постов**, счётчик живой
  (`MessagesMenuCount`), перечитывается по событиям сообщений и при переходах.
- **Страница автора**: при запрете — причина текстом (кнопки «Написать» нет), «Запретить
  писать» видна всегда, кроме своей страницы.
- **Список при событиях**: новое сообщение в показанном диалоге поднимает строку на месте,
  всё остальное (новый диалог, удаление, прочитано в другой вкладке, переподключение)
  перечитывает первую порцию.
- В dev при первой компиляции новых маршрутов overlay показал «Encountered a script tag»;
  повторно не воспроизвелось (4 чистых прогона).
- Не проверены вживую: лимиты 30 / 20 / 200, «Показать более ранние» (сообщений меньше
  50), догрузка списка порциями, догрузка после переподключения, бан собеседника.
