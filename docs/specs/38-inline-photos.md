# 38. Фото внутри текста поста

| | |
|---|---|
| Статус | done — проверено в браузере, `38-inline-photos.plan.md` |
| Lifecycle | `post.md` — раздел «Галерея» |
| Источник идеи | спека 30, «Не сделано»: в макете фото стоят посреди текста |
| Зависит от | 08 (markdown), 14 (редактор), 16 (галерея), 25 (правка вне черновика), 30 (мозаика после текста) |

## 1. Цель

Текст поста — один markdown, галерея — отдельная таблица, и на странице мозаика идёт
после текста. В макете фото и подписи вставлены между абзацами. Нужно ставить фото из
галереи в нужное место текста.

## 2. Решения

1. **Синтаксис** — `![](gallery:<imageId>)` отдельным абзацем (обсуждено). Вариант
   «после абзаца N» отвергнут: съезжает при любой правке текста. Картинки по внешнему
   URL по-прежнему запрещены — только фото галереи этого поста.
2. **Подпись — только из галереи** (обсуждено): `post_images.caption`. `alt` в markdown
   игнорируется при показе; редактор пишет пустой `alt`. Правка подписи в галерее меняет
   её и в тексте.
3. **Одно фото — один раз в тексте** (обсуждено). Повтор — ошибка поля `content` при
   сохранении: «Это фото уже есть в тексте».
4. **Рендер** (`PostMarkdown`) — блок `gallery:<id>` заменяется фото 1600/800
   (`srcSet`), с подписью под ним и ссылкой на страницу фото (спека 30, шаг 7) там, где
   мозаика ссылочная (`linked`). Id, которого нет в галерее поста, — ничего не выводит
   (страховка; при сохранении такие ссылки вычищаются, п. 7). `PostMarkdown` получает
   картинки галереи параметром. `SitePageMarkdown` картинки по-прежнему режет.
5. **Мозаика после текста** показывает только фото, которых нет в тексте. Все в тексте —
   мозаики нет. Листание на странице фото — по всей галерее, как сейчас. То же — в
   превью модератора (`PostReviewPreview`) и в просмотре в кабинете.
6. **Редактор** — встроенный `imagePlugin` MDXEditor (4.3.4), свой плагин не пишем:
   - `imagePreviewHandler` превращает `gallery:<id>` в адрес варианта 800 для показа в
     поле; неизвестный id — заглушка «фото удалено»;
   - `ImageDialog` заменён своим окном: сетка миниатюр галереи, клик вставляет блок; фото,
     уже стоящие в тексте, — серые, не выбираются (п. 3);
   - кнопка «Фото из галереи» в панели. На странице создания галереи ещё нет — кнопка
     неактивна с подсказкой «Сначала сохраните черновик и добавьте фото»; пустая
     галерея — та же подсказка про фото;
   - ресайз и настройки картинки библиотеки выключены (`disableImageResize`,
     `disableImageSettingsButton`);
   - список фото редактор получает из той же загрузки, что `PostGalleryManager`, и
     видит новые/удалённые фото после `router.refresh()`.
   Если `imagePlugin` не заработает малой кровью — запасной путь (обсуждено): блок
   вставляется вручную в `PostMarkdownField` тем же синтаксисом, кнопка «Фото из
   галереи» тогда дописывает строку в конец поля.
7. **Удаление фото из галереи** — `deletePostImageAction` в той же транзакции вычищает
   блоки с этим id из `posts.content` (удалять можно только в `draft`, п. 9). Если форма
   была открыта со старым текстом, ссылка вернётся при сохранении — поэтому сохранение
   **молча выбрасывает** `gallery:<id>`, которого нет в галерее поста. Пометка «фото
   удалено» в сохранённом тексте не нужна.
8. **Валидация сохранения** (`posts.content`):
   - картинка с адресом не `gallery:<id>` (внешний URL, `data:`, относительный путь) —
     ошибка поля: «Можно вставлять только фото из галереи поста»;
   - `gallery:<id>` не из галереи поста — выбрасывается (п. 7);
   - повтор — ошибка (п. 3).
9. **Правка вне черновика** — вставка, перестановка и удаление фото в тексте — изменение
   содержимого (спека 25): только в `draft`, проходит модерацию вместе с текстом.
10. **Обложка** может стоять и в тексте: на странице поста обложка не выводится (только
    карточки и OG), дубля нет.
11. **Выдержка, время чтения, RSS, OG** (`postText.ts`) — блоки фото в текст не
    считаются, в выдержку не попадают.
12. **Демо** — 2–3 поста из `scripts/seed-demo/` получают 1–2 фото внутри текста
    (id известны только после вставки картинок — `fill.ts` подставляет их в `content`
    после записи галереи). Остальные — с мозаикой после текста, видно оба варианта.

## 3. Данные

Нет новых таблиц и миграций. Ссылки живут в `posts.content`. Разбор ссылок — одна
функция в `domains/posts/shared/` (регулярка по `![...](gallery:<id>)` или mdast), её
используют валидация, вычистка при удалении, рендер, мозаика и `postText.ts`.

## 4. UI

- Рендер — `domains/posts/components/PostMarkdown.tsx` (`react-markdown`, кастомный `img`
  вместо `disallowedElements`), мозаика — `PostGallery`.
- Редактор — `domains/posts/components/editor/` (`PostEditorView`, окно выбора фото),
  `PostContentEditor` прокидывает картинки.
- Макет — есть (фото посреди текста на странице поста). Окно выбора фото — по образцу
  сетки `PostGalleryManager`, отдельный макет не нужен.

## 5. Вне scope

Несколько фото в ряд внутри текста, обтекание текстом, видео, картинки по внешнему URL,
подпись, отличная от подписи в галерее.

## 6. Обсуждено

- Синтаксис — `gallery:<id>` в markdown, не «после абзаца N».
- Запасное markdown-поле — согласны, если `imagePlugin` не пойдёт.
- Подпись — только из галереи.
- Одно фото в тексте — не больше одного раза.
- Удаление фото вычищает текст сразу; висячие ссылки при сохранении выбрасываются молча.

## Отклонения

- **П. 10 — обложка на странице поста есть** (спека 30: `ui-post__cover` над текстом), пункт
  устарел. Чтобы не было дубля: если обложка (`coverImageId ?? первое фото`) стоит в тексте,
  верхнюю обложку не показываем ни на странице поста, ни в `PostReviewPreview`
  (`inlineCover` в `shared/postImages.ts`, реш. 4 плана).
- **«Отдельным абзацем» — гарантия рендера, а не хранения.** Хранимый текст не нормализуется:
  фото может оказаться в одном абзаце с текстом (узел картинки в Lexical inline). Рендер
  (`remarkGalleryPhotos`) режет такой абзац на «текст → фото → текст», фото всегда выводится
  блоком `<figure>` (реш. 2 плана).
- **Демо:** в посте «Териберка» в тексте стоят все 4 фото, в том числе первое (обложка) — видно
  и «мозаики нет», и «обложка в тексте — верхней обложки нет». У Дагестана в тексте два фото, у
  Алтая — одно, первое фото у них не ставится, верхняя обложка остаётся.
- **Превью фото в редакторе — без `useRef`** (реш. 6–7 плана): `imagePlugin` получает свежий
  `imagePreviewHandler` через свой `update`, а чтение ref в рендере запрещает lint React
  Compiler. Обработчик — `useCallback` по `images`: после удаления фото и `router.refresh()`
  картинка в поле сразу становится заглушкой «Фото удалено», а не после повторного открытия.
- **Вычистка в цитате и списке** (найдено на проверке): абзац с фото внутри контейнера удаляется
  без пустой строки после — иначе следующий абзац верхнего уровня уезжал внутрь цитаты/пункта
  (`> ![](gallery:1)\n\nb` → `> b`). Остаётся пустая строка `> ` — на рендер не влияет.
  Пустой пункт списка (`- ![](gallery:1)` → `- `) не убираем: редкий случай.
- **Проверка (фаза 4):** сценарии 1–10 плана прошли. Drop файла проверен синтетическими
  событиями, настоящий drag из ОС — нет. Фото внутри ссылки (`[![](gallery:1)](url)`, только
  руками в запасном поле) не разрезается — `<figure>` внутри `<p>`; не обходим.
