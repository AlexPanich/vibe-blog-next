# 56. Поиск по смыслу и «Похожие истории»

| | |
|---|---|
| Статус | код — план `56-semantic-search.plan.md` |
| Lifecycle | `post.md` — короткий раздел «Поиск по смыслу» (статусы, переходы и права не меняются) |
| Источник идеи | `docs/ideas/ai.md`, п. 3 |
| Зависит от | 05 (поиск в ленте), 30 (страница поста, «Ещё у автора»), 33 (поиск в шапке), 54 (обёртка `globals/ai.ts`, `config/ai.ts`) |

## 1. Цель

Спеки 54 и 55 показали генерацию: модель пишет текст и структурированные ответы. Эта спека
показывает «настоящий» ML поверх базы — эмбеддинги. У каждого опубликованного поста есть вектор
смысла, и по нему работают две вещи:

- **«Похожие истории»** под статьёй: посты на ту же тему, даже если в них нет тех же слов и рубрик.
- **«Похоже по смыслу»** в ленте с поиском: запрос «куда съездить зимой у моря» находит посты, где
  нет ни одного из этих слов. Заодно поиск обходит побайтовый `LIKE` по кириллице.

Векторы — фундамент для RAG-чата (идея 4), но сам чат в эту спеку не входит.

## 2. Как сейчас

- Поиск в ленте — `filter.search` в `loadFeed.ts`: `lower_ru(title || lead || content) LIKE %q%`.
  Сюда же ведёт поиск из шапки (`HeaderSearch` → `/posts?search=`). Лента листается бесконечно
  (`FeedList`), у неё есть сортировки и фильтры (тип, рубрики «И», автор, период).
- Страница поста `app/(public)/posts/[id]/page.tsx`: статья, затем вне `article` — секция «Ещё у
  <автора>» (`authorMorePosts`, 3 карточки `PostCardBridge`, `.ui-post-more`).
- Автор опубликованный пост не правит: «Изменить» возвращает его в черновик, и после правок пост
  снова проходит модерацию. **Текст опубликованного поста меняется только между публикациями.**
  Статус меняется только через `changePostStatus`.
- Модель — только через `globals/ai.ts`, реализации — в `core/llm/` (`ollamaParse`,
  `anthropicParse`), настройки — в `config/ai.ts` по `AI_PROVIDER` (`local` / `anthropic`).
  Своих эмбеддингов у Anthropic нет.
- Демо — около 45 опубликованных постов, на Render работают без ключей.

## 3. Решения

### Векторы

1. **Провайдер следует за `AI_PROVIDER`.** `local` — Ollama, `POST /api/embed`, модель
   `OLLAMA_EMBED_MODEL` (по умолчанию `bge-m3`: многоязычная, 1024 измерения, контекст 8k).
   `anthropic` — Voyage AI, `POST https://api.voyageai.com/v1/embeddings`, ключ `VOYAGE_API_KEY`,
   модель `VOYAGE_MODEL`. Модель по умолчанию — актуальная многоязычная модель Voyage, конкретное
   имя выбрать на этапе плана по документации. У Voyage передаётся `input_type`: `document` для
   поста, `query` для запроса. SDK не нужен — хватит `fetch`.
2. **Эмбеддинги включаются отдельно от генерации.** `local` — нужен `OLLAMA_URL`, `anthropic` —
   нужен `VOYAGE_API_KEY`. Ключ Anthropic без ключа Voyage даёт генерацию без эмбеддингов, и
   наоборот. Флаг — `embedEnabled` в `globals/ai.ts`.
3. **Обёртка.** `aiEmbed({ texts, kind: 'document' | 'query' })` в `globals/ai.ts` возвращает
   нормализованные векторы (`Float32Array`, длина 1) и имя модели. Реализации — `core/llm/ollamaEmbed.ts`
   и `core/llm/voyageEmbed.ts`, настройки приходят параметрами (таймаут, модель, адрес/ключ). Код фичи
   не знает о провайдере. Ошибки — `LlmError`, как у `aiParse`.
4. **Один вектор на пост.** Текст для вектора — заголовок, lead и плоский текст (`plainText`) через
   пустую строку, обрезанный до 8000 символов. Посты в блоге короткие, а разбиение на куски нужно
   только RAG-чату (идея 4). Картинки и подписи к фото не учитываются.
5. **Хранение** — таблица `post_embeddings`: `postId` (PK, FK `posts`), `model`, `textHash`
   (sha256 текста из п. 4), `vector` (BLOB, `Float32Array`), `createdAt`. `sqlite-vec` не берём:
   нативное расширение не окупается на демо-объёме. Сходство — скалярное произведение
   нормализованных векторов в JS по всем опубликованным постам. Пост удаляется → его вектор
   удаляется явно в той же транзакции.
6. **Когда считается.** При переходе в `published` в `changePostStatus` векторы считаются в
   `after()`, как разбор ИИ в спеке 54. Совпали `textHash` и `model` — запрос к модели не идёт:
   пост вернули на публикацию без правок. Ошибка модели не роняет переход. Вектор просто не
   появляется, и пост досчитает добор из п. 7.
7. **Добор недостающих.** При чтении (п. 9, 12) берутся опубликованные посты без вектора или с
   вектором другой модели. Если такие есть, в `after()` запускается добор: пачками по 16 текстов на
   запрос. Добор один на процесс (флаг в `globalThis`), а неудачная попытка повторяется не чаще раза
   в 5 минут. Отдельный скрипт не нужен: после `db:seed`, `db:seed-dev`, смены модели или провайдера
   векторы досчитываются сами при первых посещениях. Пока добор идёт, работают те векторы, что уже
   есть.
8. **Модель сменилась** (другой `model`) — векторы старой модели не сравниваются с новыми: из разных
   пространств. Пока пост не пересчитан, у него нет вектора — для п. 9 и п. 12 это одно и то же.

### «Похожие истории»

9. **Где.** Новая секция на странице поста, после «Ещё у <автора>», тот же вид `.ui-post-more` +
   `.ui-post-grid`: заголовок «Похожие истории», **3 карточки** `PostCardBridge`. Из выдачи
   исключаются сам пост и посты, уже показанные в «Ещё у автора».
10. **Отбор.** Только `published`, порог сходства — `SIMILAR_MIN` (п. 15). Выше порога меньше трёх
    постов — показывается сколько есть, ни одного — секции нет.
11. **Без векторов.** Если эмбеддинги выключены или у поста ещё нет вектора, похожие подбираются по
    общим рубрикам: больше общих рубрик выше, при равенстве — новее. Блок есть всегда, в том числе на
    демо Render без ключа Voyage. Вид секции в обоих режимах одинаковый, подпись не меняется.
    Модель недоступна при включённых эмбеддингах — похожие по уже сохранённым векторам: на странице
    поста модель не вызывается.

### «Похоже по смыслу» в ленте

12. **Где.** Только в ленте `/posts` с непустым `search`. Поиск по словам не меняется: та же выдача,
    сортировки, пагинация и бесконечная прокрутка. **После** `FeedList` — секция «Похоже по смыслу»:
    до **6 карточек** постов, которых нет среди найденных по словам. Исключаются все совпадения по
    словам, а не только первая страница: отдельный запрос только по id.
13. **Фильтры** (тип, рубрики, автор, период) действуют и на смысловой блок: тот же `where`, что у
    ленты, без условия `search`. Сортировка внутри блока — по сходству.
14. **По словам ничего.** Вместо пустого состояния «Ничего не нашлось» — короткая строка «По словам
    ничего, но вот похожее по смыслу» и блок. Если пуст и блок, остаётся обычное пустое состояние.
15. **Порог.** `SEARCH_MIN` и `SIMILAR_MIN` зависят от модели: у bge-m3 и Voyage разное распределение
    сходства. Значения — в `config/ai.ts` по провайдеру, подобрать на демо-данных на этапе проверки.
    Стартовые значения — в плане.
16. **Запрос к модели — не на пути рендера.** Блок обёрнут в `<Suspense>` с заглушкой (скелетон
    трёх карточек), лента по словам рисуется сразу. Ошибка модели или таймаут (5 с) — блок молча
    пропадает, лента работает.
17. **Длина запроса.** Меньше 3 символов после trim — блока нет. Запрос обрезается до 200 символов.
18. **Кэш и лимит.** Вектор запроса хранится в памяти процесса (ключ — модель + нормализованный
    запрос: trim, нижний регистр `ru`, схлопнутые пробелы). До 500 записей, 1 час. Повторный поиск и
    смена фильтров модель не дёргают. Обращения к модели, которые не попали в кэш, ограничены limiter-ом
    `aiSearch` по IP: 20 в минуту. Сверх лимита — блока нет, ошибки нет (скил `rate-limit`).

### Прочее

19. **Что уходит наружу.** В Voyage (режим `anthropic`) уходят тексты опубликованных постов — они и
    так публичны — и поисковые запросы гостей без IP и пользователя. В `.env.example` — комментарий
    об этом.
20. **Живой канал и RSS** не меняются. Новый пост в ленте без перезагрузки (спека 22) смысловой блок
    не пересчитывает.
21. **Сид.** Векторы в сид не пишутся (п. 7): они зависят от модели, а модель задаёт окружение.
22. **Env** — `OLLAMA_EMBED_MODEL`, `VOYAGE_API_KEY`, `VOYAGE_MODEL`, все необязательные; описать в
    `.env.example` и в разделе «ИИ» `CLAUDE.md`. `render.yaml` — `VOYAGE_API_KEY` как необязательный
    секрет (`sync: false`).

## 4. Не входит

- RAG-чат «Спросить блог» (идея 4) и разбиение на куски.
- Смысловой поиск в кабинете (`office/posts`, админские списки) и в `HeaderSearch` до перехода в
  ленту (подсказок в шапке нет — спека 33).
- Гибридная выдача в одной ленте (слова + смысл в одной сортировке) — обсуждено, отклонено: ломает
  сортировки и прокрутку.
- `sqlite-vec` и любые индексы ANN.

## 5. Проверка

1. Без `OLLAMA_URL`: «Похожие истории» по рубрикам, в ленте с поиском смыслового блока нет, ошибок
   в консоли нет.
2. С Ollama (`bge-m3`) на свежем `db:seed-dev`: первое открытие поста запускает добор. Через
   несколько секунд похожие — по смыслу: у поста о зимнем море — другие посты о море и зиме, даже с
   другими рубриками.
3. Лента `/posts?search=куда съездить зимой у моря`: по словам ничего, блок по смыслу находит посты
   о море. Поиск «горы» — совпадения по словам сверху, в блоке — посты о походах без слова «горы»,
   без повторов.
4. Фильтр по типу или рубрике сужает и смысловой блок.
5. Пост снят с публикации и снова одобрен без правок — модель не вызывается (`textHash`). С правками —
   вектор пересчитан.
6. Смена `OLLAMA_EMBED_MODEL` — старые векторы не используются, добор пересчитывает все.
7. Остановить Ollama: лента и страница поста открываются, блок по смыслу пропадает, похожие — по
   сохранённым векторам (по рубрикам — только у постов без вектора).
8. Повторный поиск того же запроса не обращается к модели (кэш), 21-й новый запрос за минуту — без
   блока.
9. Режим `anthropic` с `VOYAGE_API_KEY` — то же, что п. 2–3.

## 6. Отклонения при реализации

1. **Модель Voyage — `voyage-4`** (план, реш. 1): серия 4 — текущая, 3.x — legacy. 1024 измерения,
   как у bge-m3; `voyage-4-large` / `voyage-4-lite` — через `VOYAGE_MODEL`.
2. **Удаления постов в приложении нет** (реш. 10 плана): п. 5 («вектор удаляется в той же
   транзакции») относится к будущему удалению. Посты удаляет только `scripts/seed-dev.ts`, и
   `post_embeddings` стоит в его зачистке перед `posts`.
3. **Длина запроса — 100, а не 200** (реш. 14 плана): `postFeedFilterDto` уже режет `search` на
   `.max(100)` с `catch`, более длинный запрос превращается в `undefined`, отдельная обрезка не нужна.
4. **Пороги bge-m3 — `searchMin 0.42`, `similarMin 0.5`** (стартовые из плана — 0.45 / 0.55),
   подобраны на демо-данных при проверке в браузере. Соседние темы у запросов дают 0.42–0.51, у
   постов — 0.50–0.60; случайные посты — медиана 0.30–0.36 у запросов и 0.38–0.44 у постов. При 0.55
   у поста оставался один похожий, по «горы» отсекался Казбек (0.43). Короткие запросы шумят и с
   новым порогом («сплав по реке» → «Плов»), однословный «еда» блока не даёт. Voyage-4 не проверен,
   пороги стартовые: `0.35` / `0.5`.
5. **Похожие при недоступной модели — по сохранённым векторам** (п. 11, проверка п. 7): в спеке было
   «по рубрикам», но векторы постов уже посчитаны, а странице поста модель не нужна. Рубрики — только
   когда эмбеддинги выключены или у поста нет вектора. Найдено при проверке в браузере, исправлен текст.
