# 39. Ручной «Выбор редакции»

| | |
|---|---|
| Статус | черновик — решения предложены, не обсуждены |
| Lifecycle | `post.md` — новый раздел «Выбор редакции», «Кто что видит» |
| Источник идеи | спека 30, «Не сделано»: выбор редакции — не редакция, а лучшая оценка недели |
| Зависит от | 07 (оценки), 20 (уведомления), 30 (`homeFresh`, `PostFeatured`) |

## 1. Цель

Метка «Выбор редакции» на главной сейчас честно не выбор: это пост с лучшей средней
оценкой за 7 дней (`homeFresh` в `homeBoard.ts`). Нужно дать редакции выбирать руками,
оставив автоматику запасным вариантом.

## 2. Решения (предложены)

1. **Кто выбирает** — moderator и admin. Кнопка «Выбрать для главной» на странице
   опубликованного поста (видна только им) и в очереди модерации у опубликованных.
2. **Один выбранный пост** в каждый момент: новый выбор снимает прежний. Выбор действует
   7 дней, потом главная возвращается к автоматике.
3. **Автоматика** — без ручного выбора как сейчас: лучшая оценка недели. Метка в этом
   случае — «Лучшее за неделю», а «Выбор редакции» — только у ручного.
4. **Пост ушёл из публикации** — выбор снимается сам (главная берёт только `published`).
5. **Автору** — уведомление `post.featured` «Ваш пост выбрали для главной».
6. **История** — записи в `post_moderations` не нужны; храним, кто и когда выбрал.

## 3. Данные

`posts.featured_at integer NULL`, `posts.featured_by integer NULL` (`ADD COLUMN` руками).
Текущий выбор — пост с наибольшим `featured_at` за последние 7 дней. Тип уведомления —
только в TS.

## 4. UI

`homeBoard.ts` (`homeFresh`), `PostFeatured` (подпись метки), кнопка — домен `posts`,
action в `postModerationActions.ts`. Макет — кнопка на странице поста для модератора.

## 5. Вне scope

Несколько выбранных постов, расписание выбора, подборки.

## 6. Открытые вопросы

- Срок действия выбора — 7 дней или пока не выберут другой?
- Подпись автоматики — «Лучшее за неделю» или оставить «Выбор редакции» для обоих?
