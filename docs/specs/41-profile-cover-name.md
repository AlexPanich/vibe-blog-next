## 1. Цель

Две правки профиля, обе — новые поля в `users`:

- баннер профиля сейчас — обложка последнего поста автора или цветная плашка; в макете —
  своя картинка;
- под постом блок «Ещё у автора» — в макете «Ещё у Ани»: имя склонять мы не умеем.

## 2. Решения

**Обложка**

1. Загрузка в `office/profile` рядом с аватаром: jpeg/png/webp до 5 МБ, варианты по
   ширине 1600 и 800 (`saveImageVariants`), кадрирование — `cover` по центру, как
   показано на странице.
2. Нет своей — как сейчас: обложка последнего поста, без неё — плашка.
3. Своя обложка главнее обложки поста везде, где сейчас берётся обложка поста: баннер
   `AuthorHead` на `/authors/[id]` (вариант 1600, srcset 800) и карточки `AuthorSpotlight`
   на `/authors` (вариант 800).
4. Удалить свою — кнопкой; admin удаляет чужую на странице пользователя с записью в журнал,
   как аватар: новый тип действия `cover_removed`, причина **необязательна** (поле есть,
   можно не заполнять), уведомление владельцу `user.cover_removed`. Свою admin удаляет
   обычной кнопкой профиля, как аватар.

**Имя в родительном падеже**

5. Необязательное поле «Как вас называть в подписях: „Ещё у …“» — одно слово или два,
   до 40 символов, подсказка «Ани», «Марата Хасанова».
6. Где используется — «Ещё у <имя>» под постом. Нет поля — «Ещё у автора», как сейчас.
   Автоматического склонения нет: для имён оно ошибается. Пробелы по краям обрезаются,
   пустая строка — `NULL`.

**Демо**

7. В `scripts/seed-demo/` — родительный падеж у всех людей из `people.ts`, своя обложка —
   у нескольких (3–4), чтобы были видны оба случая баннера.

## 3. Данные

`users.cover_key text NULL`, `users.name_genitive text NULL` (CHECK длины на колонке) —
`ADD COLUMN`. better-auth поля не знает: пишут свои actions, как `bio`. `getAuthor`
отдаёт оба поля.

## 4. UI

`AuthorHead` (баннер), `AuthorSpotlight` (`/authors`), форма профиля в кабинете, `app/(public)/posts/[id]/page.tsx`
(заголовок «Ещё у …»), admin — `office/admin/users`. Макет — уже есть (баннер профиля).

## 5. Вне scope

Позиция кадра обложки (перетаскивание), склонение в других местах интерфейса.

## 6. Lifecycle

В `docs/lifecycles/user.md` при реализации: раздел «Обложка профиля» рядом с «Аватар»
(п. 1–4), `cover_removed` в журнале admin, `user.cover_removed` в уведомлениях, поле
`name_genitive` среди полей профиля.

## 7. Обсуждено

- Склонение — поле, которое заполняет сам человек (п. 5–6); без поля — «Ещё у автора».
- Причина при удалении чужой обложки — необязательная, как у аватара (п. 4).
- Своя обложка — и на странице автора, и в карточках `/authors` (п. 3).

## 8. Отклонения от плана

- `scripts/seed-dev.ts` подчищал свежие файлы обложек как устаревшие: в набор `fresh` добавлены
  `images.covers`.
- Admin-удаление обложки дополнительно делает `revalidatePath('/authors/<id>')` — как
  `replaceImage` при своём удалении.
- В админке dto удаления аватара и обложки общий: `userRemoveAvatarDto` → `userRemoveImageDto`.
- Демо-обложки: `anya` (`kosa-1`) и `nina` (`fog-1`) из тройки «Больше всего читателей», `marat`
  из тройки — без своей; вне тройки — `timur` (`kazbek-1`) и `liza` (`ladoga-1`).
