# 16. Картинки поста: галерея, обложка, комментарии к картинкам

| | |
|---|---|
| Статус | done |
| Lifecycle | `post.md` — галерея как часть содержимого; `comment.md` — комментарии к картинке |
| Источник идеи | next-2, спеки 02 «Картинки», 27 «Обложка», 08 (комментарии к картинкам `:item=image`) |

## 1. Цель

У поста есть галерея: автор загружает фотографии, выбирает обложку, подписывает. Читатель
листает картинки на отдельных страницах и обсуждает каждую в комментариях. Обложка
украшает карточку в ленте и превью ссылки.

## 2. Решения

Обсуждены с человеком:

1. **Галерея — часть содержимого**: добавлять, удалять, подписывать и выбирать обложку
   можно только в `draft`, как текст, рубрики и тип; галерея проходит модерацию.
2. **Обложка — выбор из галереи**, по умолчанию первая картинка. Видна в карточке ленты и в
   OpenGraph-картинке.
3. **Страница картинки** `/posts/[id]/images/[imageId]`: картинка крупно, подпись,
   «← предыдущая / следующая →», под ней комментарии — то же дерево, реакции и модерация,
   что у поста (спека 15). Отдельная ветка на каждую картинку.
4. **jpeg / png / webp до 5 МБ, до 10 картинок на пост.** Сервер пережимает в webp-варианты
   1600 / 800 / 400 px по длинной стороне — фото с телефона можно грузить как есть.
5. **Подпись необязательная**, до 200 символов: видна на странице картинки и служит
   `alt`. Без подписи `alt` — «<заголовок поста>, фото N».
6. **Удаление картинки в черновике удаляет и её комментарии** (с реакциями);
   подтверждение называет последствие: «Удалятся и N комментариев». Журнал скрытий
   остаётся.

Приняты по аналогии (проверить):

7. **Файлы — в `storage/uploads/`**, путь — в `config/`. Отдаёт их route handler
   `app/uploads/[file]/route.ts` с долгим кэшем: `public/` не годится — production-сервер
   не отдаёт файлы, появившиеся там после сборки. Имя — случайный ключ, по нему не угадать
   чужие файлы; принимается только `^[a-f0-9-]+-(1600|800|400)\.webp$` — без обхода путей.
8. **Загрузка — server action, по файлу на запрос**: прогресс по каждому файлу, лимит тела
   action поднимается до 6 МБ, а не до 50. Выбор файлов: кнопка и перетаскивание.
9. **Проверка — на сервере по содержимому** (`sharp` читает формат), а не по расширению и
   MIME от браузера; клиент проверяет размер и тип заранее, чтобы не гонять 5 МБ зря.
   Ограничение 40 Мп — защита от «бомбы» из маленького файла с гигантским разрешением.
   EXIF (геометка!) снимается, ориентация применяется до этого.
10. **Порядок — по загрузке**, перестановки нет. Обложка — отдельная отметка.
11. **Галерея на странице поста** — сетка превью 400 px под текстом, у каждой — число
    комментариев. Клик — страница картинки.
12. **Модератор видит галерею** на странице модерации — она часть того, что он одобряет.
13. **Комментарии к картинке — те же `comments` с `imageId`**: права, состояния, журнал,
    лимит — общие (спека 15). Блок под постом считает только комментарии поста. «Мои
    комментарии» ведут на страницу картинки.
14. **Лимит загрузки** — 60 файлов в час на пользователя.
15. **Файлы удаляются после транзакции**: запись в БД удалена — файлы стираются; упало
    стирание — останется мусор на диске, но не битая ссылка в посте. Загрузка наоборот:
    сначала файлы, потом запись; запись не удалась — файлы стираются.

## 3. Данные

- `post_images`: `id`, `postId`, `fileKey`, `width`, `height`, `caption`, `createdAt`;
  индекс по `postId`.
- `posts.cover_image_id` — nullable (`ADD COLUMN`), null — первая картинка.
- `comments.image_id` — nullable (`ADD COLUMN`), индекс; null — комментарий к посту.

## 4. UI

- Кабинет, правка черновика: блок «Картинки» под формой — сетка превью с подписью
  (правится в строке), «Сделать обложкой», «Удалить»; зона «Перетащите или выберите
  файлы». На странице создания — «Картинки добавляются после создания черновика».
- Кабинет и модерация, просмотр поста: галерея только для просмотра.
- Публичная страница поста: галерея под текстом. Лента: обложка сверху карточки.
- Страница картинки: хлебная крошка «← К посту», картинка 1600, подпись, навигация,
  комментарии.

## 5. Вне scope

Перестановка, обрезка и поворот в интерфейсе, картинки внутри текста markdown, лайтбокс,
картинки в комментариях, скрытие отдельной картинки модератором (неподходящая — повод
отклонить пост), CDN и внешнее хранилище.

## 6. Что показала проверка

- **Обход пути**: `/uploads/..%2F..` Next отвечает 400 сам, `%2e%2e%2f` и чужие имена —
  404 по шаблону имени; файл базы недостижим.
- **EXIF**: jpeg с ориентацией 6 и GPS превращается в портрет 800×1200, в webp метаданных
  нет. Размеры в БД — уже после поворота (`metadata().autoOrient`).
- **OpenGraph**: Satori не понимает webp — обложка перекодируется в png 480×630 и
  встраивается data URL справа от текста.
- **Лента**: карточка с обложкой выше соседних, и сетка растягивала их пустотой —
  `.ui-grid { align-items: start }`.
- Лимит 10 картинок проверен на сервере: страница думала, что место есть, сервер ответил
  409, а уже записанные варианты стёрлись.
