## 1. Цель

В макете у путешествия — маршрут из нескольких точек, длина пути и число дней. Сейчас у
поста одна точка (`posts.lat`, `posts.lng`) и CHECK `posts_type_fields_check`, который
требует её у `travel`.

## 2. Решения

1. **Точки маршрута** — от 1 до **20** (обсуждено), упорядоченные, у каждой — координаты
   и необязательная подпись («Махачкала», «Гуниб»): обычный текст, края обрезаются,
   пустая — `NULL`, до 60 символов. Одна точка — как сейчас «Место на карте».
2. **Длина** — **по прямой** (обсуждено): сумма расстояний между соседними точками по
   формуле гаверсинуса, считается при показе в JS, не хранится. Подпись — «≈ 412 км по
   прямой»: по дорогам мы не считаем, и честнее это сказать. Округление — до целых км,
   меньше 1 км — «< 1 км». При одной точке длины нет.
3. **Дни** — необязательное число `travel_days` (1–365), вводит автор. Из дат не
   выводим — дат у точек нет. Разрешены и при одной точке (поездка в одно место).
   Склонение — «1 день / 3 дня / 5 дней».
4. **Редактор** — карта: клик добавляет точку в конец списка, метку можно перетащить
   (меняет координаты). Под картой — список точек: номер, поле подписи, кнопки **↑/↓**
   (обсуждено: без drag-and-drop библиотеки, работает с клавиатуры и на телефоне) и
   удаление. Первая точка обязательна, удалить последнюю оставшуюся нельзя. При 20
   точках клик по карте ничего не добавляет, под картой — подсказка о лимите.
   Поле «Дней в пути» — рядом со списком.
5. **Показ на странице поста** — линия по точкам (`Polyline`), пронумерованные метки
   (`divIcon`, без картинок — см. CLAUDE.md про Leaflet), карта подгоняет границы под
   все точки. Под картой — «Маршрут поездки · ≈ N км по прямой · M дней» и
   нумерованный список подписей (точки без подписи в списке — «Точка 3»).
6. **Мета-строка** (`PostTypeMeta`) — одна точка: как сейчас, координаты ссылкой на OSM.
   Несколько точек: вместо координат — «≈ N км · M дней» (без ссылки). Дни без длины
   (одна точка) — координаты и «M дней».
7. **Карточка ленты** — **тоже показывает** «≈ N км · M дней» (обсуждено). Точки
   грузятся одним дополнительным запросом по id travel-постов страницы ленты, длина
   считается в JS; в карточку уходит готовое число км, не точки.
8. **Совместимость** — `posts.lat/lng` остаются первой точкой: на них держится CHECK
   `posts_type_fields_check`, а пересобрать `posts` нельзя (на неё ссылаются). Читают их
   сейчас только `PostTypeMeta`, `shared/postDetails.ts` и карта на странице поста
   (в черновике спеки ошибочно упомянуты фильтры и OpenGraph — их нет). Все точки,
   включая первую, — в отдельной таблице. Миграция переносит нынешнюю точку каждого
   travel-поста как точку с `position = 0`.
9. **Смена типа** — уход с `travel` стирает точки и `travel_days` в той же транзакции
   (как остальные поля прежнего типа, `post.md` «Тип»).
10. **Правка вне черновика** — изменение маршрута и дней — изменение содержимого
    (спека 25): только в `draft`, проходит модерацию. Модератор видит маршрут в превью.
11. **Демо** — 3–4 travel-поста из `scripts/seed-demo/` получают маршрут из 3–6 точек с
    подписями и `travel_days`; остальные остаются с одной точкой (видно оба варианта).

## 3. Данные

`post_route_points`: `post_id`, `position` (0–19), `lat`, `lng`, `label`; PK
`(post_id, position)`. CHECK на диапазоны координат, `position` и длину `label` —
таблица новая, пересборки нет. Сохранение поста пишет точки целиком (delete + insert) и
`posts.lat/lng` = точка 0 в одной транзакции. При удалении поста точки удаляются явно
(внешние ключи проверяются — см. раздел 7).

`posts.travel_days integer NULL`, CHECK `travel_days IS NULL OR (type = 'travel' AND
travel_days BETWEEN 1 AND 365)` — на колонке, `ADD COLUMN` руками (как `0009_post_types.sql`).

Request: у варианта `travel` вместо `lat`/`lng` — `points: [{ lat, lng, label }]`
(1–20) и `travelDays` (необязательное). Resource деталей поста — `points` и
`travelDays`; ресурс карточки — `routeKm` и `travelDays`.

## 4. UI

`domains/posts/components/map/` — карта маршрута (показ) и редактор точек, оба через
`dynamic(..., { ssr: false })` с заглушкой той же высоты. Блок карты на странице поста,
`PostTypeMeta`, карточка ленты. Макет блока «Маршрут поездки» уже есть в Pencil
(страница поста); редактор маршрута — нарисовать перед реализацией.

## 5. Вне scope

Маршрут по дорогам (внешний сервис), импорт GPX, даты у точек, фото на точках, вставка
точки между соседними кликом по линии (порядок правится кнопками ↑/↓).

## 6. Обсуждено

- Длина — по прямой, без OSRM.
- Лимит — 20 точек.
- Порядок — кнопки ↑/↓, без drag-and-drop.
- «≈ N км · M дней» — на странице поста и в карточке ленты.
- GPX — не нужен (вне scope).

## 7. Отклонения при реализации

- **Демо-маршруты сверены с текстом постов**, а не взяты из плана как есть. Дагестан:
  Махачкала → Чиркейское водохранилище → Гуниб → Чох → Салтинский водопад (Сулакский каньон
  в тексте «пропустили», Гамсутля в тексте нет). Алтай — по дням текста: Бийск → Манжерок →
  Чике-Таман → слияние Чуи и Катуни → Курай. Ладога — три точки: в тексте только старт,
  финиш и стоянки на островах.
- **`scripts/seed-dev.ts`** чистит и `post_route_points`: сид упал на внешнем ключе. В
  соединениях better-sqlite3 `PRAGMA foreign_keys` включён по умолчанию — это расходилось с
  `CLAUDE.md` («не включён») и с комментарием в `seed-dev.ts`. Проверка через `sql-dev` не
  доказательство (MCP сам делает `foreign_keys = ON`); на чистом соединении `better-sqlite3`
  тоже `1`. После проверки исправлены `CLAUDE.md` и комментарии в `seed-dev.ts`, `schema.ts`,
  `tagActions.ts`; код не менялся.
- **Плашка типа в карточке**: текст обёрнут в `.ui-post-card__type-text` — многоточие не
  работает на текстовом узле внутри `inline-flex`.
- **Строки поста в кабинете** (`withRowData`) тоже получают `routeKm` — они идут через
  `withCardData`; лишний запрос только при travel-постах на странице.

## 8. Проверка

Пункты 1–8 плана пройдены (браузер, `sql-dev`, `tsc`, `lint`, `build`). Найдено и исправлено:

- **Номер на метке карты не по центру кружка.** `.leaflet-marker-icon { display: block }` из
  `leaflet.css` грузится позже `layout.css` и с той же специфичностью перебивал `inline-flex` у
  `.ui-map__num`. Добавлено правило `.leaflet-marker-icon.ui-map__num { display: inline-flex }`.

Замечено при проверке, исправлено следом:

- Дни 0 / 366 из UI до сервера не доходили: Mantine `NumberInput` при blur зажимал значение в
  1–365. Теперь `clampBehavior="none"` — значение уходит как есть, под полем «От 1 до 365».
- Длина без разделителя разрядов — «≈ 5695 км». Теперь `toLocaleString('ru-RU')`: «≈ 5 695 км».
- Вне спеки: zod-сообщения у `url`, `title` и `content` поста были по-английски («Too small: …») —
  заданы свои.
