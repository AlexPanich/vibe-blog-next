# 43. Статистика автора: просмотры и новые комментарии

| | |
|---|---|
| Статус | реализовано (`43-author-stats.plan.md`), следующая фаза — проверка |
| Lifecycle | `post.md` — кому видны цифры поста |
| Источник идеи | спека 42, «Не сделано»: плитка «Просмотры за 7 дней», цифры в «Моих постах» и админке, «Новый» у комментариев |
| Зависит от | 07 (оценки), 15 (комментарии), 19 (подписки), 23 (комментарии к моим постам), 42 (кабинет) |

## 1. Цель

В макете кабинета есть цифры, которых в данных нет:

- «Просмотры за 7 дней» на `/office` — число, рост к прошлой неделе (+18%), столбики по дням;
- просмотры у каждого опубликованного поста в «Моих постах» и в «Админ — Все посты»;
- пометка «Новый» у комментария к моему посту и «N новых» в плитке «Комментарии».

Подписчики (+N за неделю), средняя оценка и число комментариев считаются из того, что уже
есть, — они в спеке 42, не здесь.

## 2. Решения

Обсуждены: п. 3 (гости и суточная уникальность), 4 (очистка), 6 (видимость). Остальные
приняты как предложены.

**Просмотры**

1. Просмотр — открытие публичной страницы поста `/posts/[id]` (не карточка в ленте, не
   фото галереи). Считаются только опубликованные посты.
2. Не считаются: автор поста, staff на ревью, боты (по User-Agent, грубый список).
3. Гости считаются. Повтор от одного зрителя в течение суток не считается (уникальность
   суточная, не «за всё время»). Зритель — id пользователя или, у гостя, хеш IP +
   User-Agent + дата (соль из env, читается в `config/`; сырой IP не храним). Дата в хеше
   не даёт связать гостя между днями.
4. Храним агрегат по дням, а не каждое событие: `post_views_daily (post_id, day, views)`
   + таблица дневной уникальности `post_view_seen (post_id, day, viewer_hash)`. Строки
   старше 2 дней удаляются при записи просмотра (изредка, например на первом просмотре
   нового дня в процессе), а не задачей очереди: у plainjob в проекте нет расписания, и
   очистка не зависит от worker.
5. Запись — не в рендере страницы, а отдельным запросом после гидрации (клиентский
   компонент шлёт server action / `route.ts` один раз), чтобы prefetch и кэш не
   накручивали.
6. Видят цифры только автор (свои посты) и admin (все). Читателям — ни на странице поста,
   ни в карточках ленты: это статистика кабинета, а публичный счётчик провоцирует
   накрутку.

**Новые комментарии**

7. «Новый» — комментарий к моему посту, оставленный после того, как я последний раз
   открывал вкладку «К моим постам». Храним `users.comments_seen_at` (одно поле, без
   таблицы прочтений), обновляем при открытии вкладки.
8. «N новых» в плитке на `/office` — по тому же полю.

## 3. Данные

- `post_views_daily (post_id, day text 'YYYY-MM-DD', views int)`, PK `(post_id, day)`.
- `post_view_seen (post_id, day, viewer_hash)`, PK по трём колонкам.
- `users.comments_seen_at` — `ADD COLUMN`, NULL = «всё новое» (или дата регистрации).
- Очистка `post_view_seen` — при записи просмотра (п. 4), задачи очереди нет.
- Соль хеша гостя — новая переменная env (имя — в плане), в `.env.example`.

## 4. UI

Большая плитка на `/office` (макет «Кабинет — Начало»: фиолетовая, столбики пн–вс,
сегодня — жёлтым), колонка «Просмотры» в `PostRow` у опубликованных и в таблице админки,
пометка «Новый» в `office/comments`.

## 5. Вне scope

Источники трафика, время чтения, графики дольше 7 дней, просмотры фото галереи.

## 6. Открытые вопросы

Закрыты (п. 3, 4, 6 решений):

- Просмотры читателям не показываем — только автору и admin.
- Гостей считаем, по хешу IP + User-Agent + дата с солью.
- Уникальность суточная.

## 7. Реализация — отклонения от плана

- Маяк вызывает action напрямую (`recordPostViewAction(postId)`), без `useAction`: ответа нет,
  состояние не нужно. Метка в `useRef` осталась.
- `commentsSeen.ts` кроме `takeCommentsSeen` отдаёт `commentsSeenAt(userId)` — чтение без
  отметки для «N новых» на «Начале».
- Сид: просмотры за две недели — у опубликованных, у архивных (`hidden`) — только давние дни
  (иначе в «Моих постах» у архивного всегда 0). Отметка `comments_seen_at` — у Ани (3 дня
  назад: 5 из 16 комментариев «Новый»), а не у bob и alice: у bob один чужой комментарий, у
  alice — ни одного. У остальных NULL — у bob его комментарий тоже «Новый».
- Отдельный генератор `rng(43)` для просмотров в сиде: остальные демо-данные не сдвигаются.
- Headless Chrome с UA по умолчанию (`HeadlessChrome`) не считается — попадает под фильтр ботов
  (`headless`). Для e2e-проверки просмотров нужен обычный UA в контексте Playwright.

Проверено: `tsc`, `lint` (без новых предупреждений), `build`; в браузере — плитка «Просмотры за
7 дней» и тренд, подзаголовок, глаз с числом в «Моих постах» и на «Начале», колонка в админке
(десктоп и 390px), запись просмотра гостем и вошедшим, повтор и автор не считаются, «Новый» и
«N новых» пропадают после открытия вкладки. Не проверено в браузере: «Показать ещё» с
пометками (у демо-пользователей нет больше 20 комментариев к постам).
