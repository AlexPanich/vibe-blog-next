# 05. Лента — план

Спека: [05-feed.md](05-feed.md). Миграций нет.

## 1. Функции SQLite: `globals/db.ts`

`initClient` регистрирует на соединении:

- `lower_ru(s)` — `toLocaleLowerCase('ru')`, `deterministic`;
- `sort_ru(s)` — то же плюс `ё → е`.

Живут только в нашем соединении: drizzle-kit и MCP `sql-dev` их не знают — в миграциях и
разовых запросах их не использовать. Записать в `CLAUDE.md`.

## 2. Фильтр и URL: `domains/posts`

- `dto/postFeedRequests.ts` — `postFeedFilterDto`: `search` (trim, пустое → нет), `sort`,
  `author` (`z.coerce` положительное целое), `period`, `tag` (строка или массив), `limit`
  (округление вверх до кратного 20, в пределах 20…200). Каждое поле — свой `.catch`:
  битое значение не роняет остальные.
- `shared/feedUrl.ts` — `feedUrl(filter)`: параметры в фиксированном порядке, значения по
  умолчанию не пишутся. Без `server-only` — нужен и клиенту.

## 3. Запрос: `shared/loadFeed.ts` (server-only)

`loadFeed(filter, offset, limit)` → `{ posts, total }`:

1. Слаги рубрик → id, неизвестные выкидываются (решение 9 спеки 04).
2. `where`: `published` + поиск (`lower_ru(title || ' ' || content) LIKE ? ESCAPE '\'`,
   экранирование `\`, `%`, `_`) + автор + период (`createdAt >= now - N дней`) + рубрики
   (подзапрос «И» из спеки 04).
3. id порции — core-select с join `users` (нужен для `sort_ru(users.name)`), `orderBy` по
   сортировке, у всех вариантов последним `id` — стабильный порядок для смещения.
4. `total` — `count()` по тому же `where`.
5. Посты порции — `db.query.posts.findMany` по id с автором и рубриками, порядок
   восстанавливается по списку id. Relational API для самой выборки не годится: ему
   нужна сортировка по колонке другой таблицы.

## 4. Action: `actions/postFeedActions.ts`

`loadFeedAction` — `actionClient` (публичный), вход: фильтр + `offset`; выход — порция
ресурсом `postListResource` и `total`. Отдельного лимита нет — чтение, от флуда защищает
proxy.

## 5. Компоненты

- `FeedSearch` (server) — GET-форма на `/posts`: поле `search`, скрытые поля остальных
  условий (без `limit`), кнопка «Найти», крестик-ссылка без `search`.
- `FeedControls` (client) — три Mantine `Select` с подписями; выбор → `router.push(feedUrl(…))`
  без `limit`. Авторы приходят ресурсом.
- `FeedList` (client) — начальная порция, `total`, фильтр. Состояние списка, полоса-триггер,
  `IntersectionObserver`, догрузка с дедупликацией, `history.replaceState` с новым
  `limit`, индикатор, «Повторить». На странице получает `key` из URL без `limit` —
  смена условий сбрасывает состояние.
- `TagFilter` (tags) — проп `hrefFor(slugs)` вместо своего `feedUrl`: ссылки рубрик
  сохраняют остальные условия.
- `PostList` — убрать переключатель «Карточки / Таблица».

## 6. Страница `/posts`

Разбор фильтра → авторы с опубликованными постами (сортировка `localeCompare('ru')`) →
рубрики со счётчиками → `loadFeed(filter, 0, filter.limit)` → разметка из спеки §4.
Счётчик: «Найдено N» при поиске, иначе «Показано X из N». Пусто — «Ничего не нашлось» и
«Сбросить всё».

## 7. Проверка

- `tsc`, `lint`.
- Данные: временно добавить 45 опубликованных постов разным авторам (в т.ч. с «Ёлка»,
  «яблоко», «100%» в тексте), по окончании удалить.
- Сценарии:
  1. Первая порция 20, счётчик «Показано 20 из N»; прокрутка → 40, URL `?limit=40`;
     дубли не появились.
  2. «Назад» из поста → снова 40 карточек.
  3. Поиск «ЁЛКА» находит «ёлка», «100%» не находит «1000»; поиск + рубрика — «И».
  4. Сортировки: «старые» — порядок обратный; «по автору» — «Ёжик» между «Е» и «Ж».
  5. Автор и период сужают выдачу; неизвестные значения в URL игнорируются.
  6. Смена условия сбрасывает список к 20; ссылка рубрики сохраняет поиск.
  7. Пустой результат — «Ничего не нашлось», «Сбросить всё».
  8. `?limit=999` → 200, `?limit=abc` → 20.
