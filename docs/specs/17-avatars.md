# 17. Аватары

| | |
|---|---|
| Статус | done |
| Lifecycle | `user.md` — аватар в профиле, удаление администратором |
| Источник идеи | next-2, спека 10 «Профиль»; хранение и обработка — общие со спекой 16 |

## 1. Цель

Пользователь загружает аватар, и его видно везде, где видно имя. Без аватара остаётся
кружок с первой буквой (спека 11).

## 2. Решения

Обсуждены с человеком:

1. **Везде, где есть имя**: страница автора, карточки авторов, комментарии, шапка сайта
   (свой), админка пользователей.
2. **jpeg / png / webp до 5 МБ**, как картинки поста; сервер обрезает по центру в квадрат.
3. **Admin удаляет чужой аватар** в `office/admin/users/[id]` — на случай неприемлемой
   картинки; действие пишется в журнал администратора (`avatar_removed`), причина
   необязательна.

Приняты по аналогии (проверить):

4. **Своя колонка `users.avatar_key`**, а не `users.image` better-auth: туда GitHub кладёт
   внешний URL. Аватар с GitHub не показываем — внешняя картинка в каждой странице, и
   правила хранения были бы разными.
5. **Два варианта: 256 и 64 px** (webp) — крупный для страницы автора, мелкий для списков.
6. **Старый файл удаляется** при замене и удалении (в next-2 оставался — квирк их API).
7. **Шапка знает аватар из сессии**: `avatarKey` — additional field better-auth с
   `input: false`, как `roles`; клиент передать его не может.
8. **Правка — в `office/profile`**, панель «Аватар»: превью, «Загрузить», «Удалить».
9. **Лимит** — общий с загрузкой картинок (60 в час).
10. Забаненный войти не может; его аватар остаётся, пока admin не удалит.

## 3. Данные

`users.avatar_key` — nullable (`ADD COLUMN`). `USER_ADMIN_ACTIONS` += `avatar_removed`.

## 4. Вне scope

Обрезка вручную, GIF и анимация, аватар из GitHub, история аватаров.

## 5. Что показала проверка

- **Шапка в кабинете не обновлялась после загрузки.** `ClientSideInitializer` копировал
  пользователя из layout в `useState` один раз, и `router.refresh()` не менял копию — та же
  устарелость была и у ролей, просто меню кабинета берёт роли из своего ресурса. Теперь
  в кабинете пользователь берётся прямо из prop, копия в state — только в публичной части
  (`getSession` после гидрации).
- Поле «Причина» удаления аватара совпадало по подписи с причиной блокировки на той же
  странице — стало «Причина удаления».
- Попутно: «Избранное» сортировалось только по `createdAt` с точностью до секунды — две
  закладки в одну секунду шли в случайном порядке; добавлен `rowid` вторым ключом.
