# 29. Живая страница поста, тосты, уведомления и баг выхода

| | |
|---|---|
| Статус | done |
| Lifecycle | не меняется: события только показывают то, что уже разрешено видеть |
| Источник идеи | замечания человека после прогулки по блогу |
| Зависит от | 07 (оценки), 15 (комментарии), 20 (уведомления + SSE), 21 (сообщения), 22 (гостевой поток) |

## 1. Цель

Четыре замечания:

1. Тостов нет. События и личные сообщения должны всплывать на экране, сообщения — если
   человек не в переписке с отправителем.
2. Страница поста статична: новый комментарий, ответ, лайк, дизлайк, оценка видны
   только после перезагрузки. Хотим как на YouTube — у всех, кто смотрит, сразу.
3. Колокольчик копит прочитанное: перешёл по уведомлению — оно должно уйти из списка;
   нужна кнопка, которая очищает список целиком.
4. После выхода шапка остаётся «вошедшей», а на странице поста кнопки крутят спиннер
   бесконечно.

## 2. Решения

П. 7 и 10 обсуждены с человеком, остальные приняты сами — проверить:

### Выход

1. **Причина бага — пользователь в state публичного layout.** `ClientSideInitializer`
   держит `sessionUser` в state, а `useLogout` после `signOut()` уходит на
   `/auth/login` мягкой навигацией внутри того же root layout `(public)` — state не
   сбрасывается. Компоненты считают человека вошедшим и грузят «своё»: action отвечает
   отказом, `PostFavoriteButton` остаётся на `favorite === null` → `loading` навсегда.
   Из кабинета выход работает: смена root layout — полная загрузка.
2. **Выход сбрасывает пользователя в контексте** до перехода на вход. `UserContext`
   получает `setUser`; в кабинете prop из layout главнее, но там и так полная загрузка.
3. **Ошибка загрузки «своего» — не спиннер.** Кнопка, которой не удалось узнать своё
   состояние (избранное и подобные), показывает ошибку, а не `loading`.

### Колокольчик и история

4. **В колокольчике — только непрочитанные.** Клик по строке делает её прочитанной и
   убирает из списка сразу, не дожидаясь ответа; другие вкладки убирают её по
   `notification.read`. Меняет п. 2 спеки 20.
5. **«Отметить прочитанными» — в заголовке панели**, видна, пока список не пуст, и
   очищает его. Пусто — «Новых уведомлений нет».
6. **Ссылка «Все уведомления»** в подвале панели — на историю.
7. **История — `office/notifications`** (обсуждено): все уведомления, новые сверху,
   непрочитанные выделены, «Показать ещё» тем же загрузчиком. Прочитанным делает клик по
   строке, как в колокольчике; открытие страницы ничего не читает. Пункт «Уведомления» в
   меню кабинета с бейджем непрочитанных. Меняет п. 12 спеки 20 («отдельной страницы
   нет»).

### Тосты

8. **Тосты — `@mantine/notifications`**, справа снизу, до 3 на экране, 6 секунд, крестик.
   Меняет п. 3 спеки 20 («тостов нет»): колокольчик остаётся каналом, тост — только
   оповещение о новом.
9. **Тост уведомления** — на `notification.created`: аватар актора, текст, клик ведёт
   по ссылке и делает уведомление прочитанным (как клик в колокольчике). Закрытие
   крестиком ничего не читает.
10. **Тост личного сообщения** — на `message.created`, если сообщение не моё и я не на
    `/office/messages/{dialogId}` этого диалога (обсуждено: на списке диалогов и в других
    переписках тост есть). Имя и аватар отправителя, начало текста (до 100 символов),
    клик — в диалог.
11. **Без двойного тоста.** Личное сообщение создаёт ещё и уведомление
    `message.created` — для него тост уведомления не показывается.
12. **Тост — только в видимой вкладке.** Во вкладке, которая была в фоне, тост
    устарел бы к возвращению; колокольчик и счётчик сообщений всё равно обновятся.
13. **Гостю тостов нет** — у него нет ни уведомлений, ни сообщений.

### Живая страница поста

14. **Подписка на тему поста.** События поста не уходят всем: `EventSource` открывается
    с темами (`/api/events?topics=post:12`), шина шлёт событие только подписчикам темы,
    гостям тоже. Темы собирает `LiveEventsProvider` из подписчиков страницы, как флаг
    гостевого потока в спеке 22. Новые темы переоткрывают поток.
15. **Комментарии — сигнал «перечитай»**: `post.comments.changed { postId, imageId }`
    без содержимого. Блок перечитывает дерево тем же `loadComments`, что и страница, —
    скрытые тексты, удалённые и блокировки соблюдаются, в событие ничего лишнего не
    попадает (как `post.published` в спеке 22). Шлётся на создание, ответ, правку,
    удаление, скрытие и раскрытие модератором, правку модератором (спека 24).
16. **Реакции и оценка — со счётчиками**: `comment.reactions { postId, commentId, likes,
    dislikes }` и `post.rating { postId, average, count }`. Своё «нажато» и своя оценка
    событием не трогаются — их знает только своя вкладка.
17. **Ветка картинки** (спека 16) — те же события, блок фильтрует по своему `imageId`.
18. **Тема — только формат.** Сервер проверяет `post:<id>` и не больше 5 тем на поток, но
    не видимость поста: в событиях нет содержимого, а дерево перечитывается action-ом с
    обычной проверкой доступа.

## 3. Данные и транспорт

- Миграций нет.
- `NotificationItemResource` получает `type` — для п. 11.
- `message.created` получает `sender: { id, name, avatarKey }` — для тоста.
- Новые события в `LiveEvents`: `post.comments.changed`, `comment.reactions`,
  `post.rating` — тематические, отдельный список `LIVE_TOPIC_EVENT_TYPES`.
- `liveBus`: подписчик хранит набор тем, `publishTopic(topic, type, data)`.
- Перечитывание ветки — `loadCommentsAction` (гостям тоже, только у опубликованного поста).

## 4. UI

- `SiteHeader`: колокольчик (только непрочитанные, кнопка в заголовке, «Все
  уведомления») и `LiveToasts` для вошедшего.
- `office/notifications`: `.ui-section-head` + список строк как в панели.
- Страница поста: `CommentsBlock`, `CommentReactions`, `PostRatingBlock` слушают свои
  события.

## 5. Вне scope

Живые счётчики в карточках ленты, «печатает…» в комментариях, звук и браузерные
push-уведомления, настройки тостов, несколько инстансов (шина в одном процессе).

## 6. Открытые вопросы

- **Нагрузка от перечитывания.** На каждое изменение комментариев каждый зритель поста
  делает запрос. При популярном посте — подумать о payload вместо сигнала.

## 7. Что показала проверка

Прогон в браузере: alice, bob и гость в трёх окнах на посте bob (`/posts/3`).

- Комментарий alice — у bob и гостя без перезагрузки, у bob — тост уведомления. Ответ bob —
  у alice и гостя. Лайк и дизлайк alice на ответ — счётчики у bob и гостя, переключение
  снимает лайк. Оценка alice — у гостя «Нет оценок» → «5,0 · 1 оценка».
- Сообщение bob, пока alice в блоге, — один тост (без второго от уведомления); переход по
  нему ведёт в диалог; второе сообщение пришло в открытый диалог без тоста.
- Колокольчик — только непрочитанные; открытое уходит из панели, «Отметить прочитанными»
  очищает её; история показывает все; бейдж в меню.
- Выход с поста: шапка гостевая, после мягкого перехода «Блог → пост» спиннеров нет,
  избранное — «Войдите…».

Решения по ходу:

- **Пользователь сбрасывается хуком `useSetUser`** (`setUser` в `UserContext`): компоненты
  читают пользователя через `useUser`, а выход — единственное место, где его надо менять.
- **Живая копия ветки привязана к props.** После своего действия `revalidatePath` присылает
  новые props — они свежее, живая копия отбрасывается; события реакций правят текущий список.
- **Первый `open` блок комментариев пропускает** — это подключение при загрузке страницы;
  последующие (переподключение) перечитывают ветку.
- **Вместе с веткой перечитывается «своё»**: новый автор в ветке (блокировки) и новый
  скрытый (текст модератору) иначе остались бы неизвестны.
- Смена тем переоткрывает поток: события в момент переподключения теряются, как при разрыве.

- **Число подписчиков — тоже живое** (дописано человеком после проверки): тема автора
  `user:<id>`, событие `user.followers { userId, followersCount }` после подписки, отписки
  и блокировки (она снимает подписки в обе стороны — шлются счётчики обоих). Держит тему
  `UserFollowButton` — страница автора и пост. Где числа с сервера нет (гость на странице
  поста), событие его не показывает. Проверено: гость на странице автора видит 1 → 2 → 1,
  пока alice подписывается и отписывается.

Не проверены вручную: скрытие комментария модератором у других зрителей, ветка картинки
галереи, тост в фоновой вкладке, лимит 5 тем.
