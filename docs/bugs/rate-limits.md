# Rate limit: числа и логика лимитов

Найдено при ревью лимитов по скилу `rate-limit` (2026-10-21). Лимиты объявлены в
`src/globals/rateLimiter.ts`, сейчас там стоят старые числа.

## 1. Глобальные лимиты в proxy слишком тесные

**Сейчас:** `globalSec` — 30 запросов/с, `globalMin` — 300 запросов/мин с IP (`src/proxy.ts`).

**Проблема:** через proxy проходит всё, кроме статики: страницы, server actions и
RSC-prefetch каждого `<Link>` в видимой области. В prod страница-список (`.ui-rows`)
с 30+ ссылками сама упрётся в `globalSec` при первой загрузке. 300 в минуту на офис или
мобильный NAT — это несколько активных человек.

**Предложение:** порядка 100/с и 1000–2000/мин или не считать prefetch-запросы
(заголовок `next-router-prefetch`).

## 2. `signinIp` почти не выше лимита на один аккаунт

**Сейчас:** `signinIp` — 60 попыток в час с IP. У `signin` — 5 попыток в минуту
с блокировкой на 5 минут, то есть около 50 попыток в час на один аккаунт.

**Проблема:** лимит по IP должен быть заметно выше лимита по учётке. `signinIp` считает
и успешные входы, и нажатия «Отправить письмо повторно» (`resendVerificationAction`
работает с теми же limiter-ами). Офис, где утром логинятся 60 человек, упрётся в этот
лимит.

**Предложение:** 200–300 в час.

## 3. Нет лимита на аккаунт с ключом без IP

**Сейчас:** перебор пароля одного аккаунта ограничивает только `signin` с ключом
`ip:email`.

**Проблема:** с многих IP (ботнет) у каждого адреса свой счётчик, и пароль одного
аккаунта можно перебирать без ограничения.

**Предложение (по желанию, зависит от модели угроз):** limiter `signinAccount` с
ключом только по email, например 20 в час, **без** `blockDuration`: иначе любой сможет
заблокировать вход жертве. Сбрасывать при успешном входе, как и `signin`.

## 4. `signup` — мало для NAT

**Сейчас:** 5 регистраций в час с IP.

**Проблема:** попытка с уже занятым email тоже тратит очко: проверка уникальности
(`validate`) идёт после лимита. За NAT (офис, общежитие) 5 в час легко исчерпать.

**Предложение:** 10–20 в час.

## Мелочь: текст ошибки входа на английском

better-auth отдаёт «Invalid email or password», и он попадает в ошибку поля как есть.
Перевести в `throwSigninError` (`src/domains/users/actions/authActions.ts`).
